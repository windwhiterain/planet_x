## 三、`frozen/*.pxart` 为什么删：它是 v2，今天读 v3

那六份冻产物原本支撑一条判据 —— `px_protocol` 的
`the_frozen_originals_round_trip_byte_for_byte`（读进来 → 重拼 → **逐字节相同**），
它是"给 `PassSpec` 加字段是纯加法"的唯一证据。

**2026-09-28 查出两件事**：

1. **那条判据一直在静默跳过。** 它读的是 `target/oracle/pxart-frozen` —— 那个目录在
   2026-09-18 那场清理里没了（`target/` 不入 git）。而六份冻产物的**永久家**从那天起就是
   `art/anchor/frozen/`（正是锚 README 立"一份能被删掉的判据，不是判据"那条规矩时搬进去的），
   只是**没人改测试里的路径** ⇒ 靶子救活了，判据瞎了一整轮。
2. **把路径改对之后，它当场红**：六份全是 `"schema": 2`，而今天的渲染器认 **v3**
   ⇒ `scene_bytes` 直接拒（`场景描述是 v2，这份渲染器认 v3`）。
   ⇒ **那条判据永久不可满足**，不是能修的 bug。

⇒ 裁决（用户，2026-09-28）：**删掉 28 KB 的 v2 冻产物**，"读→写逐字节"这条性质改由
**今天的产物**来证（不再依赖任何冻结字节）。

⚠ **要知道这条改动丢掉了什么**：`hashes.txt` 式**跨版本**对照的能力没有了。
"新字段被写成默认值落盘"这个失败模式，从此只在**加字段时的人眼**与（若仍保留）现烘判据那一层拦。
这是明知代价的选择，不是疏忽。

## 四、行尾约定：这一格能不动一个像素而换掉所有键

（原文是 `hashes.txt` §六。**机制仍然生效**，逐文件的旧读数已随登记表一起退休。）

为什么它重要：闭包指纹哈希的是**模块源码字符串**，而源码是**从盘上读的**
⇒ 盘上那批字节是**每一个产物键的输入**。⇒ 换一份 checkout 约定不同的副本，可能
**像素一个不动，而所有产物键当场全换**。

三条要记住的：

- **⚠ `git status` 看不见这一格**：CRLF 与 LF 两份 clean 之后是**同一个 blob**
  ⇒ "git 说我干净"与"字节没变"是两件事。
- **两个方向都会咬人**：换到无转换的机器（Linux / CI）会让盘上的 CRLF 变 LF；
  而本机（`core.autocrlf=true`，**机器级**不是仓库级）重 checkout 会把盘上 LF 的那几份变大。
- **同一棵树下两种行尾并存** ⇒ 只能一份一份量，别一句"这份是 CRLF"带过。
  量法（三步，不动 `art/` 下一个字节）：
  `git ls-files --eol` → `git ls-files -s` 的 blob 字节数对比 `stat -c%s` →
  决定性的那一步 `git checkout-index --prefix=… -- <文件>`（加 `-c core.autocrlf=false` 取无转换那一份）。
- **本仓的铁律**：批量改写脚本**必须保留原行尾**（改一个字符的注释也可能顺带把整份文件的
  行尾换掉，那就是全仓换键）。
