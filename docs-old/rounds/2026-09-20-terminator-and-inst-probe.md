## 一、V2：气态巨行星的晨昏线（对着 `art/reference/gasgiant-uranus.png`）

改的都是**场景配方的材质旋钮**（图、算子、shader 一个字没改）：

| 栏 | 改前 → 改后 | 为什么 |
|---|---|---|
| `wrap` | 0.50 → **0.70** | 半透散射的"光包过去多少"：`wrapped = clamp((N·L + wrap)/(1 + wrap), 0, 1)` ⇒ 过渡带落在 `N·L ∈ [−wrap, 0]`，在正对相机的盘面上就是 **ndotl 那一栏的 `wrap/2`**：0.50 → 25%、**0.70 → 35%**、0.90 → 45% |
| `ambient` | 1.00 → **0.75** | 暗面压低一档（否则整颗球发平，0.90 那一版就是这样） |
| `limb` | 0.34 → **0.36** | 边缘那圈散射略强一点 |

三个值各出一张图并排比：0.50（偏紧）、**0.70（这一版）**、0.90（整盘发平、明暗读不出来）。
`wrap` 那一栏的换算关系是从 shader 的算式直接读出来的（不经任何仪器）。

出图 `target/shot-gasgiant.png`（960×640，198762 B，sha256 前 16 `57CE632A0B9CB40F`）。

⚠ **一支没做成的仪器（记下来，免得下次再写一遍）**：想用"行的亮度剖面"量晨昏线宽度
（`target/probe-terminator.py`：解码 PNG → 盘面中心行 → 从亮侧峰值扫 90%→10% 的跨度 / 盘面直径）。
实测它**分不开** `wrap` 0.50 与 0.90（0.577 vs 0.575）——**边缘散射项把行的峰值挪到了轮廓上**，
从那里出发扫出来的跨度本来就把整个盘面吃进去。⇒ 这一档今天的判据只能是"并排看 + 算式读出来的
那半个 wrap"，不要拿这支探针的数当证据（它连同"参考图 6 行样本"的不稳定读数一起留在
`target/` 里，随时可以再试别的口径）。

## 二、S4：把"库不在盘上就跳过"的端到端搬进探针

**问题**：`px_graphs/tests/inst_gate.rs` 里那条端到端（真装载实例库 → cook → 命中 → 键稳定）
开头有一段"库不在盘上 ⇒ 打印一行、`return`"。那就是**跳过**，而本仓的不变式是
"任何『跳过』都是判据的敌人"：一条**可能什么都不查**的判据比没有更坏（它给人一种查过了的错觉）。
它也不该由测试去补：那要 `cargo build` 出实例库，而测试里起 cargo 是另一回事。

**修**（判据拆成两半，各自都硬）：

| 哪一半 | 住哪 | 判什么 | 需要产物吗 |
|---|---|---|---|
| 计划那一半 | `tests/inst_gate.rs::every_instance_library_path_is_the_key_the_generator_planned` | 每条实例的**库路径**就是生成器算出来的那个 key；build graph 与生成物的名单条数一致；另按类型各钉一遍"类型自报身份" | **不要**（任何 checkout 都断言得了） |
| 运行那一半 | 新探针 `--bin inst_probe` | 真装载、真 cook、再算一次要命中、键要稳定 | 要（缺库就报错并把命令给出来） |

⚠ 测试里**不写手维护的实例清单**：名单从 `graph().into_nodes()` 与 `codegen().entries` 来，
多一条少一条都当场红（写死三条就是又一份会漂开的清单）。

**红/绿探针**：

```text
绿：./target/debug/inst_probe.exe
    实例算子：65×65×1647750｜命中=true → true｜key e7aded3f4563
    OK：装载、算、命中、键稳定四件事都过了
红：藏起 target/pcg/inst/48fdce1c…dll 再跑
    panicked: 实例库不在盘上（…\48fdce1c8b1d….dll）⇒ 先跑 `…\target\debug\px.exe build`
```

读数：那条测试从 **0.19 s 掉到 0.02 s**（不再 cook），而运行那一半仍有判据 ——
`inst_probe` 也是"实例库真能装载"这件事**唯一**的判据（`PxOp::LIB` 空串 + 运行期按 key `dlopen`
+ 符号按声明名拼，三件事里任何一件错，图跑起来才炸）。
