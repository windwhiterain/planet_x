# 站点自给：消耗只吃本地库存（完全禁止瞬移）

> 状态 `[x]`（机制落地 + 三档测试全绿；**A/B 单开关未做**，见 §6）
> ｜ 索引：[notes.md](../notes.md) ｜
> 关联：[集货运输](freight-collection.md)（本文是它的**对偶面**：那边管货怎么**出来**，
> 这边管货怎么**花掉**）、[经济深度](economy-depth.md)、[贸易与制裁](trade-and-sanctions.md)

用户 follow-up 原话：

> 非首都的投资的资源也需要从母星运输过去（或者使用本地产出）

三条裁决（问过一次，之后就按这三条做）：

1. **完全禁止瞬移**——不只投资：建楼、造舰进度、出厂装模块**全部**只从那处库存出；
2. **本地两用**——货栈**一份库存**既供本地建设、又等船运走（不新增状态、不动 schema）；
3. **进承包商**——没船的势力靠**雇佣市场**（本来就有）解决，不加新机制。

---

## 1. 物理：`State::stock_at` 是唯一读法

```rust
// src/model/state.rs
pub fn stock_at(&self, fid, body) -> Option<&ResourceMap>   // 首都天体 ⇒ Faction::resources；其余 ⇒ depots[(fid, body)]
pub fn stock_take(&mut self, fid, body, resource, amount) -> f64
```

一切实物消耗都走它（`src/sim/production.rs` 的 `site_affordable` + `commit_spend`）：

| 花钱的地方 | 文件:处 | 从哪出 |
|---|---|---|
| 建楼（投资预算） | `sim/construction.rs` `build_city` | `stock_at(城所在天体)` |
| 造舰进度（建造预算） | 同上 | 同上 |
| 出厂装模块 | `sim/ships.rs` `spawn_ship` + `choose_loadout` | 同上（**选装与付款读的是同一处**，否则「选了装不起的模块、`commit_spend` 钳零白送」） |
| 装船 | `sim/haul.rs` `haul_load` | `from` 是**货主首都** ⇒ 装池子（补给腿）；否则装货栈（集货腿） |

两条配套归一：

* **首都天体上不留货栈**（`sim/production.rs::merge_capital_depots`，每回合开头归一）：
  迁都把一处站点变成首都时，那处「等船运走」的货栈既不属于本地产出、也不再是
  `stock_at` 会读的地方——不并回池子，那些货**谁也拿不到**。
* **AI 的预算基数是「池子 + 各货栈」**（`autocontrol/budget.rs::read_budget`）：
  消耗改成站点库存之后，只看池子会让「矿全在殖民地货栈里、池子空着」的势力把预算算成 0。
  预算大 ≠ 能凭空花——每座城还各被**本地库存**卡一道。

## 2. 两条腿（`autocontrol/freight.rs::lanes`）

```text
出口腿  站点 → 首都   量 = exportable_at(站点) = max(0, 现货 − 保留量)
进口腿  首都 → 站点   量 = site_deficit(站点) = max(0, 保留量 − 现货) ∩ 首都现货
```

一张表按**量占比抽签**（同一枚 `(势力, 舰名, 回合, "route")` 派生骰，不消费主 `Prng`）；
`route_for` 的「续用」规则对两个方向各看一端（出口看起点还有没有净剩余、进口看终点还缺不缺）。
承包市场同样吃两条腿：`ContractState::open_mut` 改按**整条腿** `(from, to)` 索引
（从前只按 `from`，两条进口腿都以首都为起点 ⇒ 会互相认错）；
考核分母从「起运货栈有没有货」换成 `freight::lane_has_work`。

### 2.1 保留量 = **lead-time 库存**（口径改过错一次，务必按这版读）

```text
保留量 = min(计划总量, 每回合消耗速率 × 这条线一个往返的回合数) + 常备（每个建造区一套最低选装）
```

* **计划总量**（`site_build_need`）= 在建建筑的剩余 + 建造区**下一艘**的船体余量 + 最低选装；
* **消耗速率**（`site_burn`）= 两处与 `build_city` **同一把尺子**的速率上限
  （`construction_speed × speed_mod × productivity × labor` / `class_rate`）；
* **一个往返**用的是全作唯一那把尺子 `model::lane_rounds`（合同市场的考核周期也用它），
  所以深处的站点自然囤得多、近地几乎不囤——**没有魔数**；
* **常备那套最低选装**（`autocontrol::minimum_loadout` = 最便宜的武器 + 最便宜的推进，
  与 `choose_loadout` 的两条硬保证同源）**不进速率**：下水是一锤子买卖。

## 3. 实测：三个死结，都是量出来的

### 3.1 保留量用「整个计划」⇒ 全世界 0 舰

第一版把「计划总量」直接当保留量：站点把料全留下（计划永远很大 ⇒ 永远不出货），首都收不到货，
而首都自己也要料。实测 seed 7 / r150：星系矿业@地球的船坞**只差 铁 3.8** 卡了 50 回合，
全世界的船坞相继停产 ⇒ **0 舰**（对照 base 同期 28 舰）。改成 lead-time 口径后进口立刻活了
（seed 42：200 回合累计进口 772 件）。

### 3.2 反向：船坞的**船体料与模块**不在需求信号里

只算「在建建筑」时，一个**楼全建完、只剩船坞在干活**的天体需求恒为 0 ⇒ 一条补给腿都不开。
所以 `site_build_need` 必须包含**下一艘舰的船体余量 + 一套最低选装**（§2.1）。
连带一条硬保证：`choose_loadout_prefs` 从前在「库存一件都没有」时**早退返回空选装**，
那会造出**没有推进器的裸舰**（速度 0 ⇒ 永远不能当运输舰 ⇒ 运不来模块 ⇒ 更多裸舰，
正是「越穷越运不动」的死亡螺旋）。现在空库存只是让富集度评分退化，**平台兜底照旧生效**。

### 3.3 定编「一条腿配一艘船」⇒ 涓流腿吃光舰队

两条腿之后，**每个建造区**都常备一套最低选装 ⇒ 一个 12 城的势力平白多出十几条**涓流腿**
（每条一两件货）。按「一条腿一艘船」它们把整支舰队定成运输舰（实测 r1 就有 11/21），
战争舰队被抽空 ⇒ 更容易被打光 ⇒ 更造不出船。改成

```text
头数 = Σ_腿 min(1, 这条腿的货量 ÷ 一个货舱)      // needed_haulers，一条腿最多算一艘
```

之后三个种子（7/42/11，200 回合）都不再冻结，seed 7 从 **0 舰** 回到 **40 舰**。

### 3.4 顺手修的既有 bug：**图纸不跟着城走**

城倒戈时 `defect_city` 把投资/建造/忠诚叶子搬给了新主，**没搬图纸指针**。于是：
`build_city` 明写「悬空指针 ⇒ 这个建造区停产」，而 `autocontrol::blueprints` 明写
「悬空是玩家删图造成的，AI 不替他收拾」——两条规则叠起来 = **永久停产**，这座城再也造不出船。
实测（新物理下）seed 7 / r200：两个幸存势力 **20 个建造区里 18 个悬空**（都是打下来的城），
全世界造不出船。修法：`defect_city` 清掉被夺城的图纸指针（新主下一回合按自己的舰级重新建图）；
**玩家自己删图**那种悬空照旧保留停产语义。

> ⚠ 这条 bug 在 base 上**也存在**（只是被「池子在哪都能花」+ 未易主的船坞掩盖着：
> base r150 是 2/21 悬空）。它不属于本特性的范围，但**不修就测不出本特性**。

## 4. 守卫（`cargo nextest run -P full`，199 绿）

* **机制不变量**（`src/tests/sim/site_supply.rs`）：
  池子里堆满 ⇒ 非首都的楼**一寸不长**；本地有货 ⇒ 才长；首都上的城照旧花池子；
  **同一件货不可能同时出现在进出口两侧**（防乒乓）；保留量随往航程单调增。
* **两条腿与承包商**（`src/tests/autocontrol/freight.rs`）：
  出口/进口各自的定编；抽签比例；涓流腿只分到几分之一艘；
  **`a_shipless_faction_hires_carriers_for_both_directions`**——一个**一条船都没有**的势力
  把两条腿都挂出去、别人接单、自己的船真的把货运到（用户裁决「不是有运输承包商吗」的守卫）。
* 旧用例全部改写成新语义（前置工具 `export_only`：清空首都池 + 货放在**无城天体**上，
  把另一条腿与保留量隔开）。

## 5. 已知后果 / 待观察

* **世界经济重心变了**：站点的本地产出**先喂自己**，首都只收净剩余；深处站点囤得多。
  维护费、市场（在首都）那块没动。
* **舰队同时是生产力**（`freight-collection.md` §9 早就写下这条风险）：现在**消耗**也要船，
  所以战争 losses 与物流能力互相咬。实测三个种子能撑住 200 回合，更长局（400+）还没系统测。
* **未改的口子**（不属于「建造」这一类，故本轮不动）：`step_upkeep`（舰队维护费）与
  治理/娱乐预算仍从池子按价值扣——它们是**势力级**开销，不是某座城的实物消耗。
  市场买卖在首都之间（公理）不变。
* **承运人抽成**仍是「交付时自留、直接进自己首都池」（`freight-collection.md` §C3 的既定简化）。
  真正的「留在船上、拉回自己首都才算到手」需要**逐货主记货**（`Ship.cargo` 目前是平表）
  ——那是笔记里早就挂着的后续钩子，不是本轮范围。
