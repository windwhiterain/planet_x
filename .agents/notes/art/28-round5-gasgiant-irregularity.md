# 28 · 第 5 轮：气态行星条带的不规则性（用户："像个西瓜"）+ "西瓜度"仪器

用户原话：**"气态行星表面的纹理是很不规则的，你的那个像个西瓜"**。

---

## 一、诊断：为什么像西瓜

改前的条带是**纯纬度的函数**（`latbands` 实例：`phase = latitude · bands · π − …`）——
纬向条纹的宽窄、位置、走向都只由纬度决定 ⇒ 画面上就是一颗西瓜。
真实的气态行星，条带被湍流**拉成流线、会分叉、会打卷**，带的宽窄沿经度差得很远 ——
这些**不是"加噪声"能给**的，是**几何被扭曲**。

## 二、改了什么（两处，各管一半）

| 改在哪 | 机制 | 参数 |
|---|---|---|
| **图上：两级域扭曲**（`px_graphs/src/bin/gasgiant.rs`，各加一个 `field.fbm` + 一个 `field.warp`） | `field.warp` 把**采样方向**按东西/南北推开再重新取样 ⇒ 条带被拉成流线、推出分叉、在闭合等值线附近搅出**闭环**（涡） | `art/gasgiant/swirl.toml`（频率 2.30）＋ `warped.toml`（`strength` 0.16 / `lateral` 0.85）；`spots.toml`（频率 4.60）＋ `eddied.toml`（0.09 / 0.75） |
| **实例里：相位摆动 + 按纬度淡出**（`art/inst/latbands.rs`） | ① 叠两个大振幅低频摆（振幅约 1.4 rad ≈ 半个周期）⇒ 条纹**疏密不均、局部并拢**；② `fade` 让某些纬度**整片没有带** | `wobble` / `strength = 0.45 + 0.55·fade`；场景侧 `band_gain` 0.52 → 0.58 |

⚠ 两级扭曲的**尺度必须分开**（2.30 / 4.60）：同一个尺度推两次只是把同一个形状放大，
画面上不会更不规则。⚠ `field.warp` 自己带极区补偿（注释里写着"球面正确模式下极区自动按 1/sinθ 换算"），
所以两级的 `strength` 在极区也不会炸。

出图 `target/shot-gasgiant.png`（960×640，205806 B，sha256 前 16 `36126F6FF6C2DDEB`）。

## 三、把"像不像西瓜"变成一个数（`--bin field_probe`）

"不规则"从前只能靠眼睛。给 `field_probe` 加了两条读数（球面投影才有意义）：

```text
纬向可解释度 R²（西瓜度）= 按纬度分 48 箱之后的"箱间方差 / 总方差"（1 = 纯纬度的函数）
经/纬梯度比              = 沿经度的平均 |Δ| ÷ 沿纬度的平均 |Δ|
```

| 场 | 纬向可解释度 R² | 经/纬梯度比 |
|---|---|---|
| 改前（`mixed@838d4e8eb88b`，第 1 轮那版） | **0.6175** | 0.347 |
| 改后（`mixed@491dfd4f0ad4`，两级域扭曲） | **0.3658** | **0.523** |

⇒ "纯纬度能解释的部分"从 62% 降到 37%（−41%），经向梯度占比从 0.35 升到 0.52。
⚠ 这两条数**不是"好看"的判据**，只是"像不像西瓜"的判据 —— 别拿它当目标函数去刷。

## 四、系统侧：**S8 判为"这道门根本不成立"**（附探针）

原计划：让 `px_decls` 的门把 **op id** 也咬住（"名字 ↔ 类型 ↔ `px_op!` 的 id"三件合一）。
做法：`DeclFacts` 加 `op_id = O::ID`，再断言"这条 op id 在它自己那份 schema 的 `src/**` 里出现过"。

**探针把它否掉了**：把 `px_field_schema` 里 `"field.craters"` 改错一个字母（`"field.crater"`）
⇒ 门**仍然是绿的**。原因很清楚：`op_id` 是**从类型自己取的**，而那个字符串必然出现在它自己
crate 的源码里 —— 这条断言**永远不可能失败**。空判据正是本仓"任何『跳过』都是判据的敌人"
那条的同一族：**一条永远为真的判据比没有更坏**。⇒ 改动**整体撤回**（`px_decls` 回到提交态，
5 passed）。

⚠ 顺带量到一件真事（第一版门红在哪）：**同一个 op id 允许被两条声明共用** ——
`Remap` 与 `FieldRemap` 都是 `field.remap`（后者是"给实例复用的那份声明"，见
`docs/generic-op-and-graph-integration.md` §5.4）。设计如此，不是缺陷。

⇒ 结论：**清单（`TABLE`）已经有三道门**（`px_op!` 处数 == 条数 / 名字 ↔ 类型 / 事实是活的），
再加"id"这一道**咬不动**：要让它咬得动，就得让 `TABLE` 自己手写 id（等于再引入一份会漂开的清单）
或者给 `px_decls` 加"哪条有预置实现"的知识（那要它依赖实现 crate，方向是反的）。**不做**。
