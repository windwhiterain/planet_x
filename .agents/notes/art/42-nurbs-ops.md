# NURBS 算子库（曲线 / 曲面）

> 2026-09-21（`feature/nurbs-op`）。用户口径逐句是：**"给 graph 系统添加 nurbs 算子库"**，
> 范围定为**「求值 + 细分成网格（tessellation → `MeshData`）」**，验收定为
> **「解析对照的单元判据 + 一道装载门（`ops_load`）跑通一条最小图」**。

## §1 它住在四层里的哪一格

| 层 | 这一档放了什么 |
| --- | --- |
| `px_protocol` | 一个字都没加（网格走既有的 `MeshData`；缓存载荷里**没有**"资产种类"那一栏） |
| `px_graph_schema` | 一个字都没加（`Build` / `PxOp` / `px_op!` / `px_body!` 都是既有的） |
| `px_nurbs_schema` | **数据 + 声明**：`Curve` / `Surface` / `PointData`、`knot.rs` 的基函数与节点工具、算法的**可复用那一半**（`insert_knot` / `elevate_degree` / `sphere` / `circle`）、13 行 `px_op!` |
| `px_nurbs_op` | **实现**（dylib）：13 个 `px_body!` + 细分算法（`tessellate.rs`） |

选择"算法放 schema、实现放 dylib"而不是全塞实现库：几何不变性（插入节点 / 升阶）与
精确圆球是**判据直接量的东西**，而声明那一层必须能离开实现库单独编译与判据。
（`px_field_schema` 把可复用那一半放 `px_field_alg` 是同一条理由的另一半：那一半要给
**泛型实例**链，这一半不用。）

## §2 全库按 `f64`

`f32` 存不下有理二次整圆里那个权 `√2/2`：一舍入，圆就不再是圆（半径随参数漂
`~1e-4`）——而"精确圆"正是 NURBS 存在的理由。要进网格时才降到 `f32`（`MeshData`
的线格式就是 `f32`），那一步的误差是**出厂精度**，判据里单列一条。

## §3 十三个算子

造形：`nurbs.circle`（9 控制点 / 4 段 90°）、`nurbs.sphere`（纬向 `rings` 个 90° 片）。
求值：`nurbs.curve.eval` / `curve.at` / `curve.hodograph` / `surface.eval` / `surface.at`
（`*.at` 那一档的参数由**上游节点**给 —— 「在哪求值」因此可以由别的节点算出来）。
改形：`curve.insert` / `curve.elevate` / `surface.insert` / `surface.elevate`（几何一个字不变）。
细分：`curve.tessellate` / `surface.tessellate`。

## §4 判据

**解析对照**（`px_nurbs_schema/tests/analytic.rs` + 各文件内的单测）：

* 圆上每个参数点到圆心距离恒为半径（同时钉住"权是 `√2/2`""内部节点重数是 2""求值走有理 de Boor"）；
* 圆的切向量与半径垂直（商法则那条路）；
* 插入节点 / 升阶**不换几何**（同一个参数上的点不变，升阶后再量一次半径）；
* 球面 `|P(u, v)| = R`、法线沿半径；
* 基函数是单位分解（第 0 行和恒 1）、导数行和恒 0、右端点闭区间插值最后一个控制点；
* 载荷编解码逐位相同（内容寻址的地基）。

**端到端**（`px_graphs/tests/nurbs_pipeline.rs`，走 `PxOp::render` → 运行时装载 → 调符号）：

* `nurbs.sphere → nurbs.surface.tessellate`：顶点仍在球面上、**每条边恰好被两个三角形用到**、
  欧拉数 = 2（闭合球面）；
* `nurbs.circle → nurbs.curve.eval` 与 `curve.tessellate`：四分之一圈处是 `(0, R, 0)`、
  折线的点都落在圆上；
* 同一份参数跑两次逐位一样（缓存是「键 = 内容」）。

装载门（`px_graphs/tests/ops_load.rs`）里 13 条声明各取一次符号，四个实现库的身份互不相同。

## §5 踩过的九个坑（症状 → 病根）

这一档的数值代码**看起来都能跑**，九个坑里有六个是"曲线画出来像个样子、半径差千分之几"：

1. **基函数只返回第一个**：`basis(..., order)` 把 `order` 当成"表的层数"用，`order = 0`
   只算到第 0 层 ⇒ 返回 `[1, 0, 0, …]`，**求值恒等于第一个控制点**。改成"整条节点向量一起算、
   返回 `(order+1) × count` 的表"（顺便消掉"单位那一格落在哪个下标"这一整类越界）。
2. **右端点取错段**：`span` 在 `t = u_count` 上回 `degree`，那一档的基函数按 Cox-de Boor
   算出来**全是 0**（分母落在一串相等端点上）⇒ `t = 1` 求值得到原点、导数报"权的和为 0"。
   端点要回 `count − 1`。
3. **角切系数写反**：`Q_i = (1−a)P_{i−1} + a P_i` 里的 `1−a` / `a` 对调，曲线被拉向另一边；
   `t` 正好落在节点上时更明显。
4. **插入节点在**控制点**空间做**：有理曲线的 Böhm 角切必须对**齐次**控制点做
   （`w·x, w·y, w·z, w`）。对"位置"加权平均在非有理时恰好一致、一有理就漂
   （单位圆插一个节点后半径 1.0009）。
5. **中间那一段的下标区间**：`Q` 的新点下标与旧点下标**不是同一个**（新数组在那个位置宽一格），
   区间写成 `[at−p, at)` 会漏掉新点并把没算过的格子留成 0（症状又是"权的和为 0"）。
6. **数组按"个数"还是"格数"开**：`vec![0.0; count + 3]` 是"多 3 个**数**"不是"多 1 个**点**"
   ⇒ 尾巴整段留着 0。
7. **升阶系数写反**：`Q_i = a P_{i−1} + (1−a) P_i`，`a = i/(d+1)`（新点更靠近 `P_i`）。
8. **Bézier 段数**：内部节点重数 = `p` 时相邻段**共享一个控制点** ⇒ 段数是 `(count − 1)/p`，
   不是 `count/(p+1)`（8 段会算成 3 段）。曲面那一档还要注意"取线的下标公式两个方向不一样"
   （行主序里沿 u 是"步长乘 `nv`"、沿 v 是"下标乘 `nv`"）。
9. **平面法线**：逐边叉积挑最长的那条，会挑到"与某条边垂直"的方向而不是**那张平面**的法线
   （xy 平面上的圆算出 `(0.45, 0.89, 0)`）。改用 Newell 求和（把控制多边形当闭合环累加叉积）。

## §6 细分：统一细分 + 按尺度焊顶点

* **弦误差**是判据：每格"中心点偏离四角平均"超过 `tolerance` 就再切一刀（`depth` 是保底）。
* **统一**细分（所有格子同一级）而不是自适应四叉树：自适应会留下 **T 形接点** ——
  粗格那条边上有细格分出来的顶点，网格**看着**没缝（顶点就在那条直线上），
  但"每条边恰好被两个三角形用到"不成立。要真水密就得再写一套"挂点扇形"，
  这一档选了简单且真水密的那个；代价是平坦处也多切几刀。
* **焊顶点**：参数域的两条缝（u 的 0 与 1、两极那种整行退化成同一个点的纬线）在**网格下标**上
  是不同的顶点，只有焊起来才算闭合。⚠ 判"重合"用的是**与包围盒成正比**的容差
  （对角线 `·1e-6`），不是逐位相等：缝上两个点数学上是同一点，但两条路上的 `f64` 舍入不同，
  实测哪怕只差 `1e-16`，转成 `f32` 就是两个位型。
* 焊完扔 `a == b` 那种退化三角形：极点那一格的半个是退化的，留着会让"极点那条边只用了一次"。

## §7 诚实记账

* 曲线细分出来的是**零面积三角形**（几何上就是那条折线）：给它宽度是渲染那一档的事，
  这一档**没有**宽度参数，所以它现在不能直接当"线"渲染。要画线要么加 `width` 折成带子，
  要么渲染那一侧按折线走。
* `nurbs.sphere` 的 v 向节点重数是 2（`C⁰`），缝上**只有位置连续**；判据量的是位置精确
  （`|P| = R`），不是光滑。
* 这一档**没有**做：裁剪 / 布尔、曲面求交、节点移除、`C¹` 缝、自适应细分的挂点扇形。
