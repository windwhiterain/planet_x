## 二、S7（本轮的真问题）：网格"法线朝内"从前只是**打印**，症状是一颗黑球

**怎么撞上的**：V5 想把 `displace` 从 0.045 提到 0.075，出图是**一颗黑球**（只剩轮廓一圈亮边）。
控制实验：把**上一轮的**场景文档（`0e4c74520852`）重出一遍 ⇒ 正常的月亮 ⇒ 不是渲染器、不是色板
（色板审计"平均 RGB (151,151,151)"也正常）。

**证据（`mesh.cubesphere` 自己那行审计，两次 `PX_PCG_FRESH=1` 强制重算）**：

```text
displace = 0.075  法线朝内 51858、零长 0、最小点积 -1.000     ← 三分之一的顶点法线翻了
displace = 0.045  法线朝内 0、    零长 0、最小点积 0.783
```

`px_mesh_op/src/cubesphere.rs` 里 `lift = radius · (1 + displace · (shaped − sea_level))`，
法线是**面法线平滑**出来的 ⇒ 位移一大、几何在网格分辨率上自交，平滑出来的顶点法线就翻进去。
旧行为：**审计打印一行，然后照烘** —— 图烘完了、场景编过了、渲染出来是黑球，**没有一处报错**。

**修**：`eval` 返回 `Result<MeshData, String>`，`worst < 0.0`（有顶点法线朝内）**当场报错**，
报文里带三个实测过的数（朝内个数、最小点积、这一档的 `displace`）+ 两条方向（调小位移 / 把场做平滑），
并说明"场比网格还碎会被采样成尖刺"这条前提也是量过的（`planet` 0.769 / `desert` 0.476 在同一个
0.075 下朝内都是 0）。

**红/绿探针**（各一次图运行，秒级）：

```text
displace = 0.075  ⇒ Error: "这份立方球网格有 51858 个顶点的**法线朝内**（最小点积 -1.000）…"
displace = 0.045  ⇒ 网格审计：…法线朝内 0、零长 0、最小点积 0.783（照常出图）
```

⚠ **不做"自动把法线翻回来"**：翻回来只是把几何自交盖住，那张网格仍然是错的。

**副作用（必须记）**：`px_mesh_op` 是 `mesh.cubesphere` / `mesh.proxy` 身份的**一部分** ⇒
网格节点键全变 ⇒ `art/anchor/hashes.txt` §三 **第七次重登记**。同轮实测三份网格
（planet / desert / moon 的 `surface`）**内容逐字节没变**、只是键变了
（`f7b2d58f979e→bb21a15b5616`、`2bca0ecfaba9→ebce36aa67b2`、`5dcfdd877d67→10e8bb5e6484`）
⇒ 这正是"键 = 身份 + 内容"。因为 §三 这轮已经不能当像素判据，**J1 六张重出了一遍：6/6 逐字节**。
