# 40 · 第 17 轮：虚拟影图（按 `shadow_density` 稀疏分页，甲方案）

用户的口径：**"现在的 shadow 精度不够，太阳拉远的话更加"** ⇒ 影子要按**精度要求**稀疏地分配给
场景里的物体。裁决过的几件事：只有点光走分页；精度 `ρ` = **texel / 世界单位**；页表放
storage 缓冲、两级（行基址 + 逐行掩码）、**着色器自己算页**；**完全替掉**旧影子系统、不留兜底。
后来三条更正：这套逻辑**不许住 wgpu 宿主**、要写进 **scene graph**（`px-scene`）、
**每帧重建而管线不许因此重建**；参数走**框架已有的 per-pass 那一档**，不是 per-material；
**宿主什么都不该给**（相机、六面、每一页全走 pass 参数 = **甲方案**）。

---

## 一、形状（甲）

```
烘图侧（px-scene）                          运行时（宿主 + 执行器）
  vshadow::allocate  物体包围球 × ρ × 灯位      组 1 binding 0 = **这一条 pass 的参数**
    ⇒ 每一页在 atlas 的哪一格（页表）              · view_proj：宿主按 cube_face 那一面填
    ⇒ 一页一条 pass（viewport + view_page）        · view_page：烘图侧给（那一页在面 NDC 里的矩形）
  ShadowPlan 落盘：页表 / 段起点 / atlas / 六面基   组 0 binding 6 = **六面的基**（文档给，见下）
```

* **页表**：`[0] virtual_size | pages_per_side`、`[1] words_per_row`、`[2] 每面字数`、
  `[3..]` 逐面的行段（基址 1 字 + 掩码若干字）。查页 = 行基址 + 掩码 `countOneBits` 排名。
* **段起点是数组不是"段长 × 灯号"**：段长跟着 `pages_per_side` 走，而那是每盏灯自己的数。
* **深度比较是手写的**（`textureLoad` + `select`）：比较采样器取不到"某一页里的某一格"。
* **atlas 需要一份快照**（`copy_shadow_atlas`）：页 pass 一边写它、一边在组 0 绑它 ⇒
  wgpu 的 `DEPTH_STENCIL_WRITE` 独占用法当场拒。与 `scene_depth_sample` 同一颗雷、同一种收法。
  ⚠ 代价：1024×1024×6×4B = **24 MB 一帧**。收法是"影子 pass 的组 0 不绑 atlas"（那一档不采样它）。

## 二、六面的契约收成一处（用户裁决）

这条契约从前有**三份转写而且漂开了**：

| 处 | 第 4/5 面 | 其它 |
|---|---|---|
| 渲染器 `CUBE_MAP_FACES` | `4:−Z 5:+Z` | 唯一真源（深度真正落在哪一层） |
| 烘图侧 `vshadow::face_uv` | `4:+Z 5:−Z`（**反**） | v 轴在六个面上**不自洽**（2/3 面一个符号、0/1/4/5 另一个） |
| 着色器 | `4:+Z 5:−Z` | UV 轴还与烘图侧**转置** |
| `FACE_NAMES` | `[…"+z","-z"]` | `camera.rs` 注释声称"与它同序"——**是假的** |

现在：`px_protocol::scene::SHADOW_FACE_BASIS`（`[right, up2, axis]` × 6）是**唯一一处定义**，
烘图侧落进文档、宿主搬上 GPU、着色器只读它。`px_render` 加一条判据把 `CUBE_MAP_FACES` 经
Bevy `looking_at` 展开的结果与那张表**逐位钉住**。

**y 的翻转只留一处**：`v` 与 NDC y 同向（向上）、atlas 行号向下增。顺带修掉
`page_rect_in_face` 里 x/y 同号那个错 —— 页的 `viewport` 与 `view_page` 从前管着**不同的格子**
（49 页互相踩）。采样方向**不再 `flip_z`**：我们的层是渲染器按**世界空间**六面相机画的。

## 三、这一轮修掉的真缺陷（按"发现顺序"）

1. **宿主绑错 atlas**（静默）：`SHADOW_TEXTURE_RESOURCE` 还是旧名 `point_shadow_textures`，
   而帧图里叫 `point_shadow_atlas` ⇒ 找不到、**悄悄退回兜底 atlas**。跑得起来、图也出得来，
   只有影没了 —— 而"没影"看起来就像"这一版还没做影子"。
2. **atlas 的视图还是 `CubeArray`**（列表已改 `D2Array`）⇒ `create_bind_group` 当场拒、
   **整帧跑不完**。⚠ 它比"影不对"更难查：panic 在写图**之前**。
3. **页的 `viewport` 被翻译那一步丢掉**（`plan.rs` 无条件 `viewport: None`）：一页一条 pass 时
   不设 viewport 不等于"少设一次"，等于**每一页都往整层画**。
4. **页 pass 的 `view_proj` 是 64 字节占位 0**：执行器拿 `params` **直接当 uniform**、
   不会替谁补 ⇒ 顶点被乘成全 0、三角形退化成线、**一个 texel 都画不进去**。
5. **深度按 Chebyshev 算，而面相机存的是平面 w**：`max(|x|,|y|,|z|)` 是 cube 影图那套；
   我们的面是 90° 普通透视，`clip.w = dot(axis, dir)`。只在面正中央相等 ⇒ 边缘附近
   `depth` 恒偏小 ⇒ **整颗行星发暗、只剩一条亮边**。
6. **比较极性写反**：reverse-Z 下"有东西在我和灯之间"⟺ 它离灯**更近** ⟺ `stored > depth`
   ⟺ `depth < stored` —— 那才是**在影里**。原式把这一档取成了"亮"。
7. **没烘出来的资源要连着引用它的 pass 一起丢**：那条判据从前只看 `depth_target`，
   而 `copy_shadow_atlas` 两端都用被丢掉的资源（`reads`/`writes`）⇒ 产物自相矛盾、装载被拒。

### ⚠ 一条仪器教训（值两轮）

影子 atlas 的读回探针**写在准备阶段**（`executor.execute` 之前）⇒ 读到的是一张**刚建出来、
什么都没画**的纹理，六层全 0。而"六层全 0"与"页 pass 一笔没画"**长得一模一样** ——
我因此追了两轮错方向（去查页表、查 viewport、查 view_page）。
**读数必须说清"这是哪张图、什么时候读的"**，这两句我后来都补进了探针输出。

## 五、新判据档 + 量影边的仪器

* `art/scene/probe-ringsun{1,5,20}.toml`（各配一份 `-ns` = `shadows = 0` 的对照）：
  **环投到行星上** —— `rings` 是唯一一条 `cast_shadow = true` 的壳，带着一条真实的硬边。
  三档只差太阳多远（灯位 ×5/×20、强度按距离平方同步放大 ⇒ 辐照不变）。
  ⚠ 非要有它：`orbit-bare-shadow` 只有一颗行星，没有第二个投影体 ⇒ **影边在那里量不出来**。
* `target/tmp/shadow_edge.py`：把「关影子 − 开影子」的亮度差当成影子本身（⚠ 开影子只会更暗），
  取影像素最多的那一行，量"差降到峰值 20% 用了几个像素"= **影边过渡宽度**。

## 六、下一轮的第一件事（这一轮**新发现**的真缺陷）

```
probe-ringsun1   影贡献像素= 1582｜峰值= 86.35｜影边过渡= 5 像素
probe-ringsun5   影贡献像素=    0｜峰值=  0.00｜影边过渡= 0 像素
probe-ringsun20  影贡献像素=    0｜峰值=  0.00｜影边过渡= 0 像素
```

**太阳拉远之后影子整个消失**（不是变糊，是没了：5×/20× 与各自的 `-ns` 对照逐像素相同）。
而分配**不变**、灯的方向**不变**（等比放大）、行星的受光**几乎不变** ⇒ 病灶只剩**深度比较**那一档。

已经排除的：分配（读数逐字节相同）、面朝向与 UV（1× 能出影 ⇒ 那条链是通的）、
页的 viewport/view_page（同上）、清屏值（同上）。
⇒ 是一个**随距离变化**的量在把它吃掉。下一轮：在同一个片元上把 `depth` / `stored` / `face` /
`texel` 打出来，拿 1× 与 5× 对比 —— 1× 通、5× 不通，差在哪一项就是它。
最可疑的是 `normal_offset`：它按 `texel_world = 2·distance/N_virt` 缩放，
而**灯拉远时"环比行星近多少"这个深度优势按 1/d² 压缩** ——两者谁涨得快要拿数说话。
