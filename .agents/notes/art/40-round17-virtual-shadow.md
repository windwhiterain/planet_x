# 40 · 第 17 轮：虚拟影图（按 `shadow_density` 稀疏分页，甲方案）

用户的口径：**"现在的 shadow 精度不够，太阳拉远的话更加"** ⇒ 影子要按**精度要求**稀疏地分配给
场景里的物体。裁决过的几件事：只有点光走分页；精度 `ρ` = **texel / 世界单位**；页表放
storage 缓冲、两级（行基址 + 逐行掩码）、**着色器自己算页**；**完全替掉**旧影子系统、不留兜底。
后来三条更正：这套逻辑**不许住 wgpu 宿主**、要写进 **scene graph**（`px-scene`）、
**每帧重建而管线不许因此重建**；参数走**框架已有的 per-pass 那一档**，不是 per-material；
**宿主什么都不该给**（相机、六面、每一页全走 pass 参数 = **甲方案**）。

---

## 一、形状（甲）

```
烘图侧（px-scene）                          运行时（宿主 + 执行器）
  vshadow::allocate  物体包围球 × ρ × 灯位      组 1 binding 0 = **这一条 pass 的参数**
    ⇒ 每一页在 atlas 的哪一格（页表）              · view_proj：宿主按 cube_face 那一面填
    ⇒ 一页一条 pass（viewport + view_page）        · view_page：烘图侧给（那一页在面 NDC 里的矩形）
  ShadowPlan 落盘：页表 / 段起点 / atlas / 六面基   组 0 binding 6 = **六面的基**（文档给，见下）
```

* **页表**：`[0] virtual_size | pages_per_side`、`[1] words_per_row`、`[2] 每面字数`、
  `[3..]` 逐面的行段（基址 1 字 + 掩码若干字）。查页 = 行基址 + 掩码 `countOneBits` 排名。
* **段起点是数组不是"段长 × 灯号"**：段长跟着 `pages_per_side` 走，而那是每盏灯自己的数。
* **深度比较是手写的**（`textureLoad` + `select`）：比较采样器取不到"某一页里的某一格"。
* **atlas 需要一份快照**（`copy_shadow_atlas`）：页 pass 一边写它、一边在组 0 绑它 ⇒
  wgpu 的 `DEPTH_STENCIL_WRITE` 独占用法当场拒。与 `scene_depth_sample` 同一颗雷、同一种收法。
  ⚠ 代价：1024×1024×6×4B = **24 MB 一帧**。收法是"影子 pass 的组 0 不绑 atlas"（那一档不采样它）。

## 二、六面的契约收成一处（用户裁决）

这条契约从前有**三份转写而且漂开了**：

| 处 | 第 4/5 面 | 其它 |
|---|---|---|
| 渲染器 `CUBE_MAP_FACES` | `4:−Z 5:+Z` | 唯一真源（深度真正落在哪一层） |
| 烘图侧 `vshadow::face_uv` | `4:+Z 5:−Z`（**反**） | v 轴在六个面上**不自洽**（2/3 面一个符号、0/1/4/5 另一个） |
| 着色器 | `4:+Z 5:−Z` | UV 轴还与烘图侧**转置** |
| `FACE_NAMES` | `[…"+z","-z"]` | `camera.rs` 注释声称"与它同序"——**是假的** |

现在：`px_protocol::scene::SHADOW_FACE_BASIS`（`[right, up2, axis]` × 6）是**唯一一处定义**，
烘图侧落进文档、宿主搬上 GPU、着色器只读它。`px_render` 加一条判据把 `CUBE_MAP_FACES` 经
Bevy `looking_at` 展开的结果与那张表**逐位钉住**。

**y 的翻转只留一处**：`v` 与 NDC y 同向（向上）、atlas 行号向下增。顺带修掉
`page_rect_in_face` 里 x/y 同号那个错 —— 页的 `viewport` 与 `view_page` 从前管着**不同的格子**
（49 页互相踩）。采样方向**不再 `flip_z`**：我们的层是渲染器按**世界空间**六面相机画的。

## 三、这一轮修掉的真缺陷（按"发现顺序"）

1. **宿主绑错 atlas**（静默）：`SHADOW_TEXTURE_RESOURCE` 还是旧名 `point_shadow_textures`，
   而帧图里叫 `point_shadow_atlas` ⇒ 找不到、**悄悄退回兜底 atlas**。跑得起来、图也出得来，
   只有影没了 —— 而"没影"看起来就像"这一版还没做影子"。
2. **atlas 的视图还是 `CubeArray`**（列表已改 `D2Array`）⇒ `create_bind_group` 当场拒、
   **整帧跑不完**。⚠ 它比"影不对"更难查：panic 在写图**之前**。
3. **页的 `viewport` 被翻译那一步丢掉**（`plan.rs` 无条件 `viewport: None`）：一页一条 pass 时
   不设 viewport 不等于"少设一次"，等于**每一页都往整层画**。
4. **页 pass 的 `view_proj` 是 64 字节占位 0**：执行器拿 `params` **直接当 uniform**、
   不会替谁补 ⇒ 顶点被乘成全 0、三角形退化成线、**一个 texel 都画不进去**。
5. **深度按 Chebyshev 算，而面相机存的是平面 w**：`max(|x|,|y|,|z|)` 是 cube 影图那套；
   我们的面是 90° 普通透视，`clip.w = dot(axis, dir)`。只在面正中央相等 ⇒ 边缘附近
   `depth` 恒偏小 ⇒ **整颗行星发暗、只剩一条亮边**。
6. **比较极性写反**：reverse-Z 下"有东西在我和灯之间"⟺ 它离灯**更近** ⟺ `stored > depth`
   ⟺ `depth < stored` —— 那才是**在影里**。原式把这一档取成了"亮"。
7. **没烘出来的资源要连着引用它的 pass 一起丢**：那条判据从前只看 `depth_target`，
   而 `copy_shadow_atlas` 两端都用被丢掉的资源（`reads`/`writes`）⇒ 产物自相矛盾、装载被拒。

### ⚠ 一条仪器教训（值两轮）

影子 atlas 的读回探针**写在准备阶段**（`executor.execute` 之前）⇒ 读到的是一张**刚建出来、
什么都没画**的纹理，六层全 0。而"六层全 0"与"页 pass 一笔没画"**长得一模一样** ——
我因此追了两轮错方向（去查页表、查 viewport、查 view_page）。
**读数必须说清"这是哪张图、什么时候读的"**，这两句我后来都补进了探针输出。

## 六、第 17 轮下半场：找到"影随灯距消失"的根因

### 根因：组 1 上**后绑的赢**，而执行器绑早了

同一条 pass 的**同一个组号（组 1）**上有两个来源：宿主随材质给的那一份（相机那一份
`PassView`，当作"回退视图"）与这一条 pass 自己的参数块（页的影子面相机）。wgpu 的规矩是
**后绑的赢**，而执行器把参数块绑在 `set_pipeline` **之前**、材质的组**之后** ⇒
**材质那一份把参数块盖掉了**。

后果不是"少一个参数"，而是**每一页影子都拿相机的视图去画**：

* atlas 里装的是**主相机**看到的深度 ⇒ 换相机会变、**换灯距不变**；
* 于是"1× 那档看起来有影"纯属巧合；
* 用户报的"太阳拉远影就没了"就是这么来的 —— **灯距根本没进那张图**。

**指纹**（这一轮就是靠它钉死的）：

| 动作 | 修之前 | 修之后 |
|---|---|---|
| 换相机（`--cam 0,22,4.2`） | atlas 读数**变**（0.0541 → 0.0349、非零 7552 → 9538） | **不变** |
| 换灯距（1× → 5×） | atlas 读数**完全不变** | 变（真的按面相机算了） |

一个"影子图"对**相机**敏感、对**灯**不敏感 —— 那就是这一条写反的指纹。而灯位在宿主日志里
一直是对的、矩阵也确实按灯位算了（平移列 `[-2.35,-2.6,0.1,4.2]` → `[-11.75,-13.0,0.1,21.0]`）
—— **算对了却被人盖掉**，这一类只有"看最后谁赢"才查得出来。

一并删掉宿主组 1 的 **binding 1**（每实例数据）：实例数组搬去组 0 binding 21 之后没人读它，
留着只"把布局填满"，而它的代价正是上一条（执行器那份布局只声明 binding 0，
一旦后绑就撞 `Expected entry with binding 1 not found`）。⇒ 组 1 从此**只有一格**。
"没人读的绑定"就是"谁能赢"的暗规则。

### 修完之后剩下的（下一轮从这里接着走）

atlas 开始有**逐面**的内容了（层 4 非零 **16384**、最大深度 0.0394；在此之前六层读数相同
—— 那正是"六面都拿同一个相机视图"的指纹），**但影还不是环投出来的影**：

* 把「开影子 − 关影子」放大 4 倍看图：差是一块**贴着画幅左上角的实心楔形**（被画幅边缘切掉），
  不是行星上的一条环带 ⇒ 那是**屏幕空间的伪影**，不是影；
* 所以"1× 有 29436 个影像素"这个数**不可信**，它量的是那块楔形；
* 5×/20× 仍然 0，而 atlas 逐面有内容 ⇒ 查页那一环（面选择 / 页索引 / 页内 texel）还没对。

⇒ 下一轮：**先把"屏幕空间楔形"这件事从查页那一环上分出来**（它意味着某些方向的片元
恒被判成影，而那与影子图的内容无关）。1× 那 29436 个像素在此之前不能当验收读数。


```
probe-ringsun1   影贡献像素= 1582｜峰值= 86.35｜影边过渡= 5 像素
probe-ringsun5   影贡献像素=    0｜峰值=  0.00｜影边过渡= 0 像素
probe-ringsun20  影贡献像素=    0｜峰值=  0.00｜影边过渡= 0 像素
```

**太阳拉远之后影子整个消失**（不是变糊，是没了：5×/20× 与各自的 `-ns` 对照逐像素相同）。
而分配**不变**、灯的方向**不变**（等比放大）、行星的受光**几乎不变** ⇒ 病灶只剩**深度比较**那一档。

已经排除的：分配（读数逐字节相同）、面朝向与 UV（1× 能出影 ⇒ 那条链是通的）、
页的 viewport/view_page（同上）、清屏值（同上）。
⇒ 是一个**随距离变化**的量在把它吃掉。下一轮：在同一个片元上把 `depth` / `stored` / `face` /
`texel` 打出来，拿 1× 与 5× 对比 —— 1× 通、5× 不通，差在哪一项就是它。
最可疑的是 `normal_offset`：它按 `texel_world = 2·distance/N_virt` 缩放，
而**灯拉远时"环比行星近多少"这个深度优势按 1/d² 压缩** ——两者谁涨得快要拿数说话。

## 六之三、第 17 轮第三场：`LoadOp::Clear` 清的是**整份附件**

### 根因（"影图里什么都没有"的真凶）

`LoadOp::Clear` 在 wgpu/WebGPU 里清的是**整份附件**（那一层 2048² 全清），**不受 viewport
限制**。而页那一版设计是"**一页一条 clear pass**"（`page_clear_pass`，外加每页第一笔 caster
也带 `depth=clear(0)`）⇒ 第 k 页的清屏把第 1..k−1 页已经画好的深度**全抹掉**，
整层最后只剩**最后一页**那一笔的几何。

受控档 `art/scene/probe-vs-center.toml`（灯正好在 +X 轴上、没有环 ⇒ 行星必然落在面 −X 的
正中央，一切不确定性都消掉）：

| | 修之前 | 修之后 |
|---|---|---|
| 有内容的层 | 1 层 | 该有的那几层 |
| 内容的包围盒 | 挤在**页块最后一页**（正好一格 128² = 16384 个 texel） | 按物体投影铺开（34771 个 texel、跨页） |
| 内容位置 | 页块角落 | 与 `page_block_origin` 算出来的中心**对得上** |

修法：**每一层的第一条 pass 清，其余一律 `load`**（清屏那一笔的 viewport 无所谓 ——
整层都会被清）。`page_clear_pass` 整个删掉：它存在的理由就是错的。

⚠ **教训的形状**：这条与上一场的"组 1 后绑的赢"是**同一类** ——
都是"一条 pass 的某一栏**看起来**是局部的（viewport / 组号），而实际语义是全局的"。
两次都让"影图里什么都没有"，两次都要靠**受控档 + 包围盒**这种硬读数才照出来。

### 修完之后：影子第一次**随灯距变**

```
            有内容的层          最大深度        非零
probe-ringsun1   0 / 3 / 4    0.0394（d≈2.54）  656458 / 535862 / 390537
probe-ringsun5   0            0.0056（d≈18.0）   51825
```

修之前六层读数**完全相同**（"六面都拿同一个相机视图"那个病的残留）；
现在 1× 三层、5× 一层（环的角直径从 28.7° 缩到 6.3° ⇒ 落在更少的面里），
而 5× 的内容包围盒中心 (439,1670) 与 `page_block_origin` 按 `(物体−灯)` 方向算出的
(450,1657) **对得上** ⇒ **分配是对的**。

### 深度约定：已用受控档证实是**精确**的

`probe-vs-center`（灯 (5,0,0)、无环、行星半径 ≈1.06）：
按几何算最近表面 d = 5.0 − 1.06 = 3.94 ⇒ `depth = 0.1/3.94 = 0.0254`；
**实测最大深度 0.02516310 ⇒ d = 3.974** ✓ 对得上。
（环那一档 d≈2.54 看着"比几何上可能的更近"，是因为环带着行星的**轴倾**、
不落在 y=0 平面上；不是约定错。）

⇒ 下一轮不必再查深度约定与分配。病灶只剩**采样那一侧**：5× 的 atlas 是对的，
而影子出不来。

## 七、第 17 轮第四场：两套网格分开 ⇒ **验收过了**

### 模型那一半（上一轮漏掉的）

`pages_per_side` 从前与灯距无关，而**精度要求**要的是"一个 texel = 1/ρ 个世界单位"：

```
一面 90° ⇒ 距灯 d 处横跨 2d 个世界单位，这一面有 pages_per_side × 128 个 texel
⇒ 一个 texel 的世界尺寸 = 2d / (pages_per_side × 128)
⇒ 要它 = 1/ρ，就必须 pages_per_side = dρ/64 —— **与 d 成正比**
```

从前它是"某个 caster 的 span + 2 取 2 的幂"、与 d 无关 ⇒ **texel 世界尺寸 ∝ d ⇒
太阳拉远精度按比例变差** —— 正是用户报的那一条。

⚠ **判据里藏着一个 bug**：`density_is_independent_of_how_far_the_light_is` 断的是
"灯拉远**不改变分配**"（逐字段比较 `LightLayout`），而那条"不变量"**就是上面那个 bug**。
它把 bug 钉成了契约，于是修复会让判据变红、看起来像"改坏了"。
**把 bug 当不变量的判据比没有判据更糟：它会挡住修复。** 已改成断"texel 世界尺寸与灯距无关"。

### 网格那一半（这一轮）

格子变细之后 atlas 立刻炸（5× 要 16384²×6×4B = **6.4 GB**），因为
`atlas_pages = atlas_side_for(pages_per_side)` —— **两种网格被绑成一个数**。分开：

* **虚拟格子** `pages_per_side`：精度要求定的，随 d 细；
* **物理 atlas** `atlas_pages`：分出去的页数定的（`next_pow2(ceil(√页数))`），稀疏那一半。

⚠ `head[1]` 低 16 位放掩码字数（≤8）、**高 16 位放 atlas 页格边长**，着色器两处解码分开。

⚠⚠ **页的 `viewport` 也必须换成 atlas 坐标**：从前 `PagePatch.window`（虚拟格子）
同时当 viewport 与 `view_page`。两套网格分家之后不改这一处，页号稍大就超出设备的
`max_texture_dimension_2d`（实测 `y = 30464` 被 wgpu 拒）；**而改写之前 5× 一直是 0 像素**
—— atlas 的读数（内容、层、包围盒）全对，因为那些页画到了**atlas 的错格子**上。

### 验收（用户口径：影边宽度）

| 档 | 影贡献像素 | 峰值 | **影边过渡** |
|---|---|---|---|
| 1× | 63043 | 103.99 | **33 像素** |
| 5× | 14530 | 103.20 | **31 像素** |

⇒ **两档的影边过渡宽度一致（差 6%）= 精度与灯距无关**。像素总数不同是**几何**
（灯近，行星投在环上的影本来就更大），不是精度。

出图：`target/tmp/ring-probe-ringsun1.png` —— 环的左侧有一条行星投出的暗带，
形状与"行星在环上的影"一致。
