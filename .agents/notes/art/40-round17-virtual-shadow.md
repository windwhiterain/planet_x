# 40 · 第 17 轮：虚拟影图（按 `shadow_density` 稀疏分页，甲方案）

用户的口径：**"现在的 shadow 精度不够，太阳拉远的话更加"** ⇒ 影子要按**精度要求**稀疏地分配给
场景里的物体。裁决过的几件事：只有点光走分页；精度 `ρ` = **texel / 世界单位**；页表放
storage 缓冲、两级（行基址 + 逐行掩码）、**着色器自己算页**；**完全替掉**旧影子系统、不留兜底。
后来三条更正：这套逻辑**不许住 wgpu 宿主**、要写进 **scene graph**（`px-scene`）、
**每帧重建而管线不许因此重建**；参数走**框架已有的 per-pass 那一档**，不是 per-material；
**宿主什么都不该给**（相机、六面、每一页全走 pass 参数 = **甲方案**）。

---

## 一、形状（甲）

```
烘图侧（px-scene）                          运行时（宿主 + 执行器）
  vshadow::allocate  物体包围球 × ρ × 灯位      组 1 binding 0 = **这一条 pass 的参数**
    ⇒ 每一页在 atlas 的哪一格（页表）              · view_proj：宿主按 cube_face 那一面填
    ⇒ 一页一条 pass（viewport + view_page）        · view_page：烘图侧给（那一页在面 NDC 里的矩形）
  ShadowPlan 落盘：页表 / 段起点 / atlas / 六面基   组 0 binding 6 = **六面的基**（文档给，见下）
```

* **页表**：`[0] virtual_size | pages_per_side`、`[1] words_per_row`、`[2] 每面字数`、
  `[3..]` 逐面的行段（基址 1 字 + 掩码若干字）。查页 = 行基址 + 掩码 `countOneBits` 排名。
* **段起点是数组不是"段长 × 灯号"**：段长跟着 `pages_per_side` 走，而那是每盏灯自己的数。
* **深度比较是手写的**（`textureLoad` + `select`）：比较采样器取不到"某一页里的某一格"。
* **atlas 需要一份快照**（`copy_shadow_atlas`）：页 pass 一边写它、一边在组 0 绑它 ⇒
  wgpu 的 `DEPTH_STENCIL_WRITE` 独占用法当场拒。与 `scene_depth_sample` 同一颗雷、同一种收法。
  ⚠ 代价：1024×1024×6×4B = **24 MB 一帧**。收法是"影子 pass 的组 0 不绑 atlas"（那一档不采样它）。

## 二、六面的契约收成一处（用户裁决）

这条契约从前有**三份转写而且漂开了**：

| 处 | 第 4/5 面 | 其它 |
|---|---|---|
| 渲染器 `CUBE_MAP_FACES` | `4:−Z 5:+Z` | 唯一真源（深度真正落在哪一层） |
| 烘图侧 `vshadow::face_uv` | `4:+Z 5:−Z`（**反**） | v 轴在六个面上**不自洽**（2/3 面一个符号、0/1/4/5 另一个） |
| 着色器 | `4:+Z 5:−Z` | UV 轴还与烘图侧**转置** |
| `FACE_NAMES` | `[…"+z","-z"]` | `camera.rs` 注释声称"与它同序"——**是假的** |

现在：`px_protocol::scene::SHADOW_FACE_BASIS`（`[right, up2, axis]` × 6）是**唯一一处定义**，
烘图侧落进文档、宿主搬上 GPU、着色器只读它。`px_render` 加一条判据把 `CUBE_MAP_FACES` 经
Bevy `looking_at` 展开的结果与那张表**逐位钉住**。

**y 的翻转只留一处**：`v` 与 NDC y 同向（向上）、atlas 行号向下增。顺带修掉
`page_rect_in_face` 里 x/y 同号那个错 —— 页的 `viewport` 与 `view_page` 从前管着**不同的格子**
（49 页互相踩）。采样方向**不再 `flip_z`**：我们的层是渲染器按**世界空间**六面相机画的。

## 三、这一轮修掉的真缺陷（按"发现顺序"）

1. **宿主绑错 atlas**（静默）：`SHADOW_TEXTURE_RESOURCE` 还是旧名 `point_shadow_textures`，
   而帧图里叫 `point_shadow_atlas` ⇒ 找不到、**悄悄退回兜底 atlas**。跑得起来、图也出得来，
   只有影没了 —— 而"没影"看起来就像"这一版还没做影子"。
2. **atlas 的视图还是 `CubeArray`**（列表已改 `D2Array`）⇒ `create_bind_group` 当场拒、
   **整帧跑不完**。⚠ 它比"影不对"更难查：panic 在写图**之前**。
3. **页的 `viewport` 被翻译那一步丢掉**（`plan.rs` 无条件 `viewport: None`）：一页一条 pass 时
   不设 viewport 不等于"少设一次"，等于**每一页都往整层画**。
4. **页 pass 的 `view_proj` 是 64 字节占位 0**：执行器拿 `params` **直接当 uniform**、
   不会替谁补 ⇒ 顶点被乘成全 0、三角形退化成线、**一个 texel 都画不进去**。
5. **深度按 Chebyshev 算，而面相机存的是平面 w**：`max(|x|,|y|,|z|)` 是 cube 影图那套；
   我们的面是 90° 普通透视，`clip.w = dot(axis, dir)`。只在面正中央相等 ⇒ 边缘附近
   `depth` 恒偏小 ⇒ **整颗行星发暗、只剩一条亮边**。
6. **比较极性写反**：reverse-Z 下"有东西在我和灯之间"⟺ 它离灯**更近** ⟺ `stored > depth`
   ⟺ `depth < stored` —— 那才是**在影里**。原式把这一档取成了"亮"。
7. **没烘出来的资源要连着引用它的 pass 一起丢**：那条判据从前只看 `depth_target`，
   而 `copy_shadow_atlas` 两端都用被丢掉的资源（`reads`/`writes`）⇒ 产物自相矛盾、装载被拒。

### ⚠ 一条仪器教训（值两轮）

影子 atlas 的读回探针**写在准备阶段**（`executor.execute` 之前）⇒ 读到的是一张**刚建出来、
什么都没画**的纹理，六层全 0。而"六层全 0"与"页 pass 一笔没画"**长得一模一样** ——
我因此追了两轮错方向（去查页表、查 viewport、查 view_page）。
**读数必须说清"这是哪张图、什么时候读的"**，这两句我后来都补进了探针输出。

## 六、第 17 轮下半场：找到"影随灯距消失"的根因

### 根因：组 1 上**后绑的赢**，而执行器绑早了

同一条 pass 的**同一个组号（组 1）**上有两个来源：宿主随材质给的那一份（相机那一份
`PassView`，当作"回退视图"）与这一条 pass 自己的参数块（页的影子面相机）。wgpu 的规矩是
**后绑的赢**，而执行器把参数块绑在 `set_pipeline` **之前**、材质的组**之后** ⇒
**材质那一份把参数块盖掉了**。

后果不是"少一个参数"，而是**每一页影子都拿相机的视图去画**：

* atlas 里装的是**主相机**看到的深度 ⇒ 换相机会变、**换灯距不变**；
* 于是"1× 那档看起来有影"纯属巧合；
* 用户报的"太阳拉远影就没了"就是这么来的 —— **灯距根本没进那张图**。

**指纹**（这一轮就是靠它钉死的）：

| 动作 | 修之前 | 修之后 |
|---|---|---|
| 换相机（`--cam 0,22,4.2`） | atlas 读数**变**（0.0541 → 0.0349、非零 7552 → 9538） | **不变** |
| 换灯距（1× → 5×） | atlas 读数**完全不变** | 变（真的按面相机算了） |

一个"影子图"对**相机**敏感、对**灯**不敏感 —— 那就是这一条写反的指纹。而灯位在宿主日志里
一直是对的、矩阵也确实按灯位算了（平移列 `[-2.35,-2.6,0.1,4.2]` → `[-11.75,-13.0,0.1,21.0]`）
—— **算对了却被人盖掉**，这一类只有"看最后谁赢"才查得出来。

一并删掉宿主组 1 的 **binding 1**（每实例数据）：实例数组搬去组 0 binding 21 之后没人读它，
留着只"把布局填满"，而它的代价正是上一条（执行器那份布局只声明 binding 0，
一旦后绑就撞 `Expected entry with binding 1 not found`）。⇒ 组 1 从此**只有一格**。
"没人读的绑定"就是"谁能赢"的暗规则。

### 修完之后剩下的（下一轮从这里接着走）

atlas 开始有**逐面**的内容了（层 4 非零 **16384**、最大深度 0.0394；在此之前六层读数相同
—— 那正是"六面都拿同一个相机视图"的指纹），**但影还不是环投出来的影**：

* 把「开影子 − 关影子」放大 4 倍看图：差是一块**贴着画幅左上角的实心楔形**（被画幅边缘切掉），
  不是行星上的一条环带 ⇒ 那是**屏幕空间的伪影**，不是影；
* 所以"1× 有 29436 个影像素"这个数**不可信**，它量的是那块楔形；
* 5×/20× 仍然 0，而 atlas 逐面有内容 ⇒ 查页那一环（面选择 / 页索引 / 页内 texel）还没对。

⇒ 下一轮：**先把"屏幕空间楔形"这件事从查页那一环上分出来**（它意味着某些方向的片元
恒被判成影，而那与影子图的内容无关）。1× 那 29436 个像素在此之前不能当验收读数。


```
probe-ringsun1   影贡献像素= 1582｜峰值= 86.35｜影边过渡= 5 像素
probe-ringsun5   影贡献像素=    0｜峰值=  0.00｜影边过渡= 0 像素
probe-ringsun20  影贡献像素=    0｜峰值=  0.00｜影边过渡= 0 像素
```

**太阳拉远之后影子整个消失**（不是变糊，是没了：5×/20× 与各自的 `-ns` 对照逐像素相同）。
而分配**不变**、灯的方向**不变**（等比放大）、行星的受光**几乎不变** ⇒ 病灶只剩**深度比较**那一档。

已经排除的：分配（读数逐字节相同）、面朝向与 UV（1× 能出影 ⇒ 那条链是通的）、
页的 viewport/view_page（同上）、清屏值（同上）。
⇒ 是一个**随距离变化**的量在把它吃掉。下一轮：在同一个片元上把 `depth` / `stored` / `face` /
`texel` 打出来，拿 1× 与 5× 对比 —— 1× 通、5× 不通，差在哪一项就是它。
最可疑的是 `normal_offset`：它按 `texel_world = 2·distance/N_virt` 缩放，
而**灯拉远时"环比行星近多少"这个深度优势按 1/d² 压缩** ——两者谁涨得快要拿数说话。

## 六之三、第 17 轮第三场：`LoadOp::Clear` 清的是**整份附件**

### 根因（"影图里什么都没有"的真凶）

`LoadOp::Clear` 在 wgpu/WebGPU 里清的是**整份附件**（那一层 2048² 全清），**不受 viewport
限制**。而页那一版设计是"**一页一条 clear pass**"（`page_clear_pass`，外加每页第一笔 caster
也带 `depth=clear(0)`）⇒ 第 k 页的清屏把第 1..k−1 页已经画好的深度**全抹掉**，
整层最后只剩**最后一页**那一笔的几何。

受控档 `art/scene/probe-vs-center.toml`（灯正好在 +X 轴上、没有环 ⇒ 行星必然落在面 −X 的
正中央，一切不确定性都消掉）：

| | 修之前 | 修之后 |
|---|---|---|
| 有内容的层 | 1 层 | 该有的那几层 |
| 内容的包围盒 | 挤在**页块最后一页**（正好一格 128² = 16384 个 texel） | 按物体投影铺开（34771 个 texel、跨页） |
| 内容位置 | 页块角落 | 与 `page_block_origin` 算出来的中心**对得上** |

修法：**每一层的第一条 pass 清，其余一律 `load`**（清屏那一笔的 viewport 无所谓 ——
整层都会被清）。`page_clear_pass` 整个删掉：它存在的理由就是错的。

⚠ **教训的形状**：这条与上一场的"组 1 后绑的赢"是**同一类** ——
都是"一条 pass 的某一栏**看起来**是局部的（viewport / 组号），而实际语义是全局的"。
两次都让"影图里什么都没有"，两次都要靠**受控档 + 包围盒**这种硬读数才照出来。

### 修完之后：影子第一次**随灯距变**

```
            有内容的层          最大深度        非零
probe-ringsun1   0 / 3 / 4    0.0394（d≈2.54）  656458 / 535862 / 390537
probe-ringsun5   0            0.0056（d≈18.0）   51825
```

修之前六层读数**完全相同**（"六面都拿同一个相机视图"那个病的残留）；
现在 1× 三层、5× 一层（环的角直径从 28.7° 缩到 6.3° ⇒ 落在更少的面里），
而 5× 的内容包围盒中心 (439,1670) 与 `page_block_origin` 按 `(物体−灯)` 方向算出的
(450,1657) **对得上** ⇒ **分配是对的**。

### 深度约定：已用受控档证实是**精确**的

`probe-vs-center`（灯 (5,0,0)、无环、行星半径 ≈1.06）：
按几何算最近表面 d = 5.0 − 1.06 = 3.94 ⇒ `depth = 0.1/3.94 = 0.0254`；
**实测最大深度 0.02516310 ⇒ d = 3.974** ✓ 对得上。
（环那一档 d≈2.54 看着"比几何上可能的更近"，是因为环带着行星的**轴倾**、
不落在 y=0 平面上；不是约定错。）

⇒ 下一轮不必再查深度约定与分配。病灶只剩**采样那一侧**：5× 的 atlas 是对的，
而影子出不来。

## 七、第 17 轮第四场：两套网格分开 ⇒ **验收过了**

### 模型那一半（上一轮漏掉的）

`pages_per_side` 从前与灯距无关，而**精度要求**要的是"一个 texel = 1/ρ 个世界单位"：

```
一面 90° ⇒ 距灯 d 处横跨 2d 个世界单位，这一面有 pages_per_side × 128 个 texel
⇒ 一个 texel 的世界尺寸 = 2d / (pages_per_side × 128)
⇒ 要它 = 1/ρ，就必须 pages_per_side = dρ/64 —— **与 d 成正比**
```

从前它是"某个 caster 的 span + 2 取 2 的幂"、与 d 无关 ⇒ **texel 世界尺寸 ∝ d ⇒
太阳拉远精度按比例变差** —— 正是用户报的那一条。

⚠ **判据里藏着一个 bug**：`density_is_independent_of_how_far_the_light_is` 断的是
"灯拉远**不改变分配**"（逐字段比较 `LightLayout`），而那条"不变量"**就是上面那个 bug**。
它把 bug 钉成了契约，于是修复会让判据变红、看起来像"改坏了"。
**把 bug 当不变量的判据比没有判据更糟：它会挡住修复。** 已改成断"texel 世界尺寸与灯距无关"。

### 网格那一半（这一轮）

格子变细之后 atlas 立刻炸（5× 要 16384²×6×4B = **6.4 GB**），因为
`atlas_pages = atlas_side_for(pages_per_side)` —— **两种网格被绑成一个数**。分开：

* **虚拟格子** `pages_per_side`：精度要求定的，随 d 细；
* **物理 atlas** `atlas_pages`：分出去的页数定的（`next_pow2(ceil(√页数))`），稀疏那一半。

⚠ `head[1]` 低 16 位放掩码字数（≤8）、**高 16 位放 atlas 页格边长**，着色器两处解码分开。

⚠⚠ **页的 `viewport` 也必须换成 atlas 坐标**：从前 `PagePatch.window`（虚拟格子）
同时当 viewport 与 `view_page`。两套网格分家之后不改这一处，页号稍大就超出设备的
`max_texture_dimension_2d`（实测 `y = 30464` 被 wgpu 拒）；**而改写之前 5× 一直是 0 像素**
—— atlas 的读数（内容、层、包围盒）全对，因为那些页画到了**atlas 的错格子**上。

### 验收（用户口径：影边宽度）

| 档 | 影贡献像素 | 峰值 | **影边过渡** |
|---|---|---|---|
| 1× | 63043 | 103.99 | **33 像素** |
| 5× | 14530 | 103.20 | **31 像素** |

⇒ **两档的影边过渡宽度一致（差 6%）= 精度与灯距无关**。像素总数不同是**几何**
（灯近，行星投在环上的影本来就更大），不是精度。

出图：`target/tmp/ring-probe-ringsun1.png` —— 环的左侧有一条行星投出的暗带，
形状与"行星在环上的影"一致。

## 十、量影边的仪器**换掉了**（沿扫描行 → 沿梯度），验收口径重写后的一次读数

### 为什么换：原来那把尺子量的是**几何**，不是滤波

环上那条影边在画面上**斜着**穿过扫描行 ⇒ 沿行量到的"峰值降到 20% 用了几个像素"是
**掠射穿越**的宽度。点采样与真滤波在这个数上分不开（改核前后都是 15 / 13 像素），
而且**相机一转就变** —— 拿它当验收等于过不了也证不了。

### 新仪器：把「关影子 − 开影子」当成一幅图 `D`，按**梯度**量

影边是一条阶跃，被核糊成一条过渡带。幅度 `P`（取 0.99 分位，免得单个坏点顶上去）、
过渡带的**最大斜率** `max|∇D|` ⇒

```
等效宽度 w = P / max|∇D|        （单位：像素）
```

⚠ 只看 `D ∈ (0.15P, 0.85P)` 那些点（**影边**上的点）的梯度，不把环自己带的纹理梯度算进去。

* **点采样** ⇒ 阶跃几乎不糊 ⇒ 斜率极大 ⇒ `w` 趋于下界 **1.0**（一个像素的量化）；
* **真滤波** ⇒ `w` 与核宽同量级；
* **走样** ⇒ 边上出现硬台阶 ⇒ 斜率又变大 ⇒ `w` 又变小。

### 读数（`target/tmp/edge_width.py`）

| 档 | 幅度 | 最大斜率 | **等效宽度** |
|---|---|---|---|
| 1× | 99.28 | 60.228 | **1.648 px** |
| 5× | 81.06 | 49.638 | **1.633 px** |
| 20× | 74.35 | 39.357 | **1.889 px** |
| 相机近（`--cam 0,0.41,2.36`） | 85.78 | 52.892 | **1.622 px** |
| 相机远（`--cam 0,1.10,6.30`） | 88.06 | 55.004 | **1.601 px** |
| **对照：退化核（点采样）** | 99.28 | 67.214 | **1.477 px** |

⇒ **重写后的验收成立**：影边宽度在 **1–2 px** 内，且**灯距 1×/5×/20× 与相机近/远五档
全落在 1.60–1.89 px（跨度 3%）**。

⚠ 那 3% 不是"没做到更好"，是**仪器自己的下界**：完美阶跃给 1.0，点采样给 1.477，
真滤波给 1.6 上下 —— 核只有 1–2 个 texel（合 1 px 上下），所以这个量本来就只在
1.5–1.7 这个窄带里动。**能看出差别、也够判"在不在 1–2 px 里"**，但要拿它分辨"核再宽 20%"
是分辨不出来的（那要靠 2.0 texel 上限之外的场景，也就是目标 ③ 的粗级）。

## 十二、第一档"足迹远大于 2 texel"的判据档：`probe-hires`

### 为什么原来那几档走不到"选级"这一半

`texel_world ≈ 1/ρ`（因为 `pages_per_side ≈ dρ/64`，与 d 无关）⇒

```
want > 0  ⟺  足迹 > 2/ρ
```

而足迹是"一个像素在接收面上跨多少世界单位"，**由相机距离定** ⇒ 要么 ρ 大、要么相机近。
`probe-ringsun*` 那几档足迹只有 ~1.5 texel ⇒ `want = 0` ⇒ 永远读级 0。

⚠ 而 atlas 的代价按 `(ρ·R)²` 涨 ⇒ **ρ 大就必须 R 小**。所以这一档是
**小行星（radius 0.3）+ 高密度（ρ=1024）+ 近相机**，小环（`rings = 1.45` 最小值）当那个
薄投影体。烘出来：atlas 4096²、四级页数 3630 / 1158 / 444 / 192。

### 仪器又发现一个盲点：**全局 99 分位看不见小影**

这一档的影只占画面很小一块（受影响 1847–5165 像素 / 614400）⇒ 99 分位被"大片没影的区域"
拉到 0，脚本报"这一档没有影" —— **而 atlas 里明明有几百万个非零 texel**。
改成 **99.9 分位**并顺带打印**受影响像素数**（`D > 3` 的计数）：尺子看不见小影不是"没有影"。

⚠ 但**改完仍然不够**：`HiresFar` 给出 **0.623 px**，比完美阶跃的下界 1.0 还小 —— 那是
"幅度"与"最大斜率"分别取自画面里不同的地方造成的（影里那块又小又暗）。**这个读数我不当结论用**，
记在这里是为了下一次不再踩。要量小影得把幅度**局部**取（在影边邻域里取），不是全局。

### 已经拿到的硬证据：**粗级真的被读到了**

同一机位（`--cam 0,0.55,1.70`）下 A/B：

```
只画 caster 自己那一级  vs  金字塔铺满（同一机位）
mean=0.009  max=35  差>2 的 0.38%  差>8 的 0.079%
```

⇒ **成图确实不一样** ⇒ 采样侧确实读到了粗级（`want > 0` 时命中粗级），
而不是"铺了金字塔但没人读"。这是"选级"那一半**在渲染帧里活着**的第一条直接证据 ——
在此之前它只有 `px-scene` 的单元判据（页确实分到了粗级）撑着。

⚠ 这条证据**只说"粗级被读到了"，没说"读粗级更好"**。要断后者得量"有粗级 vs 退到细级"

## 十三、局部幅度版的尺子（`shadow_alias.py`）—— 仍没答出"读粗级是不是更好"

`edge_width.py` 的幅度是全局取的，影只占画面一小块时它会给出比下界 1.0 还小的数

| 档 | 受影响 | 边像素 | 局部幅度 | 等效宽度（中位） |

## 十四、把 per pass 参数做成**与 per material 一样能随便装**（用户裁决，待施工）

### 裁决原文

> 让 per pass parameters 也能像 per material 一样随便装，**凡是一个 pass 的所有几何都需要
> 使用的参数就统统放 per pass parameters**。

### 现状：这条通道是**偏移式**的，所以装不了纹理

| | 实例数 | 办法 | 能装什么 |
|---|---|---|---|
| per material（组 3） | 几个 | **一个材质一个组对象**（`ResolvedMaterial.groups` 里 `&binding.bind_group`） | 什么都行（含贴图） |
| per pass（组 1） | **几千**（页 × 6 面） | **一份缓冲 + 动态偏移** | **只有 uniform** |

理由写在 `px_render/src/render.rs:1750` 那份布局旁边：「一帧一份大缓冲 + 每笔一个偏移
（页有几百个，"一页一份绑定组"是几百个对象）」。而**动态偏移只能在一份缓冲里选一格，
它选不了纹理对象** —— 这就是"per pass 装不了纹理"的全部原因。不是 API 不许，是这条通道
被刻意做成了偏移式的。

### 好消息：模板现成，全屏 pass 早就是这么装的

`px_pass/src/lib.rs:2210` 的 `fn layout`：参数块那一格 + **对每个 slot 声明两格** ——
贴图在 `slot.binding`、采样器在 `slot.binding + 1`，资源名走 `PassPlan::reads`、
落点走 `slots`。**几何 pass 缺的只是"把那一段也用上"**：`geometry_params_group`（`:2261`）
今天只声明一格 uniform（那是刻意的：`:2252` 那段说"几何 pass 的参数只服务顶点阶段，
多一格都会让它与宿主的管线布局对不上"）。

   而影子要的是 **`Depth` + `Comparison`** ⇒ 加一栏（如 `depth: bool`）。
   ⚠ 连带一处容易漏：`Dimension::layers()`（`:762`）只喂**兜底纹理**的 `depth_or_array_layers`

## 十五、`bind_group` 那一份模板读全了（第 3 步的精确形状）

`px_pass/src/lib.rs:2329` 的 `fn bind_group` 是全屏 pass 的组构造，也就是几何 pass 要照着
扩的那一份。形状是：

```rust
fn bind_group(&mut self, device, encoder, layout, sampler: &Sampler,
              params: &[u8], bound: &[(u32, TextureView)]) -> BindGroup
```

三条关键事实（都是"不看代码猜不到"的）：

1. **一整条 pass 只用一把采样器**（`sampler` 是**单个** `&Sampler`，所有 slot 共用）。
   ⇒ 深度那一档要的是 `Comparison` 采样器，而**颜色与深度混在同一条 pass 时这把共用采样器
   就得二选一** —— 今天没有这样的 pass，但这是扩的时候必须写进注释的边界。
2. **绑定表是 `(binding, TextureView)` 的数组**，按 `slot.binding` 查；**查不到就退到兜底纹理**
   （`self.fallback(device, encoder, slot.dimension)`）—— 兜底那张今天写死 `Rgba8UnormSrgb`
   （`:2171`），而深度槽要换成深度格式，否则"没绑的槽"这张兜底图与布局类型对不上。
   ⚠ 这条与第 14 节里 `Dimension::layers()` 那条是**同一个坑的两头**。
3. 参数块那一格在这个函数里是 `has_dynamic_offset: false`（全屏那份，`:2219`）；
   几何那一份是 `true`（`:2277`）—— **两者不是同一份布局**，扩的时候别把动态偏移弄丢。

## 十六、⚠ 十四/十五两节里的**计划被推翻了一半** —— 实际落地的形状（第 18–22 轮）

不照着这一节读，会以为影子 atlas 搬去了组 1、`Layout` 长了 `geometry_slots` —— 两件都没发生。

### 换方案的原因：一次「必须裁决」的实测

十五节第 2 条自己记着那条边界（"颜色与深度混在同一条 pass 时这把共用采样器就得二选一"）。
真去接线时撞上的是**同一族但更硬**的一堵墙：降采样要「读 `atlas[k-1]` 写 `atlas[k]`」，
而 wgpu 的 `DEPTH_STENCIL_WRITE` 是**独占**用法 —— 附件同时被绑就是硬错。绕法有两条：
（甲）把 atlas 搬进材质那一组并给全屏 pass 补一份"带槽位"的布局；（乙）**别搬**，改用
「写谁就不绑谁」。用户裁决选了后者那条路（全屏 pass 也要支持 `#import`），最后落地的是：

| 从十四/十五的设想 | 实际落地的 |
|---|---|
| atlas / 采样器搬进**组 1** | **仍在组 0**（binding 2/22/23/24，四条定长链）。降采样从**自己那一格**读上一级 |
| 几何 pass 带 `reads` / `slots` | **没带**。`Plan::check` 的那两条拒收**原样留着**（执行器解析不了也验不了） |
| `Layout` 加 `geometry_slots` | 没加。`PassPlan` 加了 **`texture_slots: Option<Vec<Slot>>`**（按这份 shader 的**反射**填） |
| 宿主造 K+1 个组对象、按用途选 | `Frame` 加了 **`zero_dummy`** 一格；全屏 pass 用它 |

### 那个"哑图"为什么必须是**哑图**（本轮最贵的一课）

`cell.zero` 把**四张真 atlas 全绑上**（binding 2/22/23/24）。降采样写着 `atlas_l{k}`，
而 `cell.zero` 第 `k` 格**正好也绑着它** ⇒ 附件/资源撞车，报错里只有资源名、没有 pass 名。
所以全屏 pass 走**哑图那一档**（四格全挂 1×1 兜底；视图 / 灯 /**页表** 仍然是真的）。
它读输入走的是**自己的**第 1 格，与"写谁就不绑谁"是同一条纪律的两面。

### 全屏 pass 的槽位形状**按反射**给（不是按全局约定表）

`plan.layout` 是**一份**共享布局，形状来自 `TEXTURE_SLOTS`（颜色贴图、非深度）；
而降采样声明的是 `texture_depth_2d_array`（`D2Array` + 深度槽）。**一份布局装不下两种形状**。
现在 `px_render/src/plan.rs` 的 `fullscreen_of` 顺手反射一份 `texture_slots`，
`execute_inner` 用它拼出这条 pass 的**有效 `Layout`**，**管线与绑定组共用同一份** ——
⚠ 各用一份的症状正是「管线说 Depth、绑定组给 Float」（建组时才炸）。
深度槽还要**比较采样器**（`compare: Some(GreaterEqual)`），执行器为此多缓存了一个。

### 落地的三样东西

1. **`frag_depth` 开关**（`06e40d4`）：`RenderState` 的**可选**键。降采样的深度值只能在片元里
   算完写 `@builtin(frag_depth)`。它**不进 `STATE_KEYS`**（那是**必填**清单，"缺一格就是没说"
   那条判据要的正是"少写 = 明确的缺省"），且 `to_text` **只在开启时才写** ⇒ 从前那些
   `render` 文本逐字节不变。
2. **每级一张独立 atlas**（`ddde4f3`）：槽位**每级每面各自从 0 开始**；页格边长是
   `ceil_sqrt(那一级最多的页数)`，**不取 2 的幂**（`ceil_sqrt(481) = 23` 抬到 32 面积多 93%）。
   页表头**一个字都没改** —— 每级的页格边长靠 `textureDimensions(atlas_级).x / 128` 现算
   （烘图侧按 `atlas_sides[级]` 覆盖帧图那一栏 ⇒ 纹理正好是「页格边长 × 128」）。
3. **金字塔降采样**（`34399c5`）：级 k = 级 k-1 的**四个孩子取 max**。⚠ **取 max = 取最近的
   遮挡物 ⇒ 影只会偏大、不会漏光**；单通道装不下 (min, max) 那一对，而漏光是看得见的错、
   影偏大只是保守 —— **这条偏置是故意的**。「取 max」有**两级**：片元里对四个孩子一次，
   硬件的 `compare=greater_equal + depth_write` 与页上已有内容再一次。
   用户裁决「**粗级只由降采样生成**」⇒ `vshadow` 里几何只画到 `own` 那一级（粗级的页照旧
   分配 —— 金字塔要**铺满**）；`wanted` 只在 `level == own` 带 caster id。

### 判据（`34399c5` 那次全绿）

`probe-ringsun1` 逐级读回（`PX_AUDIT_SHADOW=1`）：级 0/1/2 的**最大深度逐位相同**
（0.03944319），非零数 2499781 → 626047 → 157044 ——**恰好 1/4**（max 幂等 ⇒ 粗级确实接住了
细级的内容）。影边宽度（梯度法的等效宽度 `w = P/max|∇D|`，**重写后的验收口径**）：
1× **1.684** / 5× **1.664** / 20× **1.778** / 相机 `0,0.41,2.36` **1.609** /
相机 `0,1.10,6.30` **1.560** px —— 全落在 **1–2 px**，与降采样之前相差 ≤ 0.05 px ⇒ 无回归。
