# 长局控制面缺口（一局 192 月实机游玩暴露的「表达不出来」）

> 状态 `[~]`（§5 已解；其余为候选，未实现） ｜ 索引：[notes.md](../notes.md) ｜ 关联：
> `control-live-layers.md`（**§5 的正解与实现**）、`ship-blueprint.md`（§6 的那个解）、
> `agent-control-api.md`（`control` 面向目标的模板）、`agent-play-friction.md` §18.1/§18.2/§18.6、
> `governance-loyalty.md`（倒戈目标过滤）、`balance-of-power.md`（合纵）

本 note 与 `agent-play-friction.md` **不重叠**：那边记的是「**看不懂状态**」（语义视图、聚合到决策的桥、
指令难写）。这里记的是**「看懂了也表达不出来」**——一局真实长局（`--seed 2026`，中国，第 0–192 月，
战记 `play/exp2/campaign.md`）里，玩家想执行的国策**在 `control` 面上根本没有对应的叶片**。
每条都带实测代价与可复现素材。

结论先行：这一局中国**先赢后崩**（r48 份额 0.343 霸权 → r72 只剩 1 城 0 舰），
**直接死因不是「不会玩」，而是控制面缺三片叶子**：维护费上限（§1）、交战规则（§2）、
放弃城市（§4）。文档 §6 教的「主动收手/制衡」，在当前控制面上**写不出来**。

## 1. 预算只有「限速」，没有「封顶」（本局翻车的直接机制）

**事实**：`construction_budget`/`investment_budget` 的 `value` 是**每种资源每月的花费速率**；
`mode=Player` 时是固定绝对值，`mode=Ai` 时是 `库存 × economy.invest_fraction(0.3)`。
**没有任何叶片表达「舰队规模上限」「维护费不超过产出的 X%」「造到 N 艘就停」**；
`build_weights` 也不是配额（本局把珠三角设 1.5、其余 0.5–1.0，并**没有**限住造舰速度——
真正限速的只有 `construction_budget` 的资源速率）。

**实测代价**：库存堆到 铁 932 / 硅 434 后，AI 于 r37–r41 连造 3 艘战列舰 + 2 艘护卫舰，
舰队 5 → 10 艘（r48 达 **16 艘**），`upkeep` 39 → 73 → **147** 对产出 66 = **2.2 倍**，
净流 **−88.8/月**；24 个月后从霸权塌成 1 城。我事后把 `construction_budget` 钉成 Player
（碳 0.8 / 铁 4.0 每月）只做到**限速**——**已经在队列里的舰照样下水**。

**引擎其实算得出这条线**：`--control-plan` 的 `fleet_upkeep_cap`（r0 = 59.95）就是 AI 用的保守上限，
但它是**只读报告**，玩家写不进去。

- `[ ]` **把「舰队维护费上限」变成可写叶片**：`{"upkeep_ceiling": {"value": 0.4, "mode": "Player"}}`
  （占产出比例）或直接暴露 `fleet_upkeep_cap`；语义 = 造舰预算触顶后归零。这是本局最想有的一片叶子。
- `[ ]` **`BudgetPatch.value` 支持「产出占比」形式**（如 `{"frac_of_production": 0.3}`）：否则长局里
  Player 固定值只有两种结局——经济涨了它饿着舰队、经济跌了它拖垮国家，玩家必须每隔 ~20 回合重调
  （本局重调了 7 次）。
- `[ ]` **让 `build_weights` 明确「是配额还是相对权重」**（或补一句「单船坞吃到整份预算」的说明），
  否则它对 agent 的暗示是错的。

## 2. 没有外交叶片 —— 文档教的国策在控制面上写不出来

**事实**：控制面只有 `ship_orders/ship_doctrine/ship_kiting/两类预算/两类权重/loyalty_budget/
capital/buildings`，**没有宣战 / 停战 / 亲善 / 制裁 / 加入或退出合纵中的任何一种**。而
`auto_combat`（敌舰入射程、敌城入围城射程即自动开火）对玩家与 AI 一视同仁；每次攻击
`diplomacy.attack_delta = −3`，关系被钉在 `hostility_floor = −60`——**只要舰队停在敌人城市旁边，
战争就永远等不到 `war_fatigue` 冷却**。

**实测代价**：`cn_us_rivalry`（r11）之后中美战争一路打到 r96（**85 个月**），我全程无法提议停火，
也无法让舰队「只守不攻」。`agent-play.md` §6 推荐的「在份额涨起来时主动收手/制衡」，
在当前控制面上**没有任何对应动作**——这正是 `agent-play-friction.md` §18.6 想教的策略，
却缺了执行它的手。

- `[ ]` **交战规则（ROE）叶片**（势力级）：`{"roe": {"siege_cities": false, "return_fire_only": true}}`。
  让「守土但不轰城」可表达——这是本局最缺的一片叶子（我 r0 只想守家，结果自动开战）。
- `[ ]` **停火/和谈意图叶片**（哪怕只是软目标：由 sim 按 `war_fatigue` 与对方意愿裁决）。
- `[ ]` **加入/退出合纵**：`balance-of-power.md` 的合纵机制已落地，但玩家只能被系统安排。

## 3. `dock <body>` 没有「驻防」语义，`Move` 又是绝对坐标

**事实**：`Dock{body}` = 绕该天体巡航，而**一个天体上常常住着好几个势力的城**
（地球：中国/美国/欧盟/俄罗斯/联合国各有一座）。于是「回本土驻守」= 自动对最近敌方城市开火：
本局 r0 我把三舰钉在 `dock 地球` 想守家，r11 就触发了美中开战、舰队开始轰亚特兰大。
另一条路也走不通——`Move{position}` 是**绝对坐标**（AU 平面点），天体在公转，
所以表达不了「距地球 0.3 AU 的待机位」这种**舰队存在（fleet in being）**姿态。

- `[ ]` `Dock{body, standoff: AU}`（在 `combat.siege_range` 之外绕行）/ `Patrol{bodies}` /
  `Intercept{body}` 行为；与 §2 的 ROE 二选一即可解。
- `[ ]` 或给 `Move` 一个**相对天体**坐标（`{"body": "地球", "offset": [x, y]}`），
  让待机位跟着天体走。

## 4. 无法放弃/拒绝城市，但城市会自动倒戈给你

**事实**：**城市倒戈不经玩家同意**。本局 r35 深空运输联盟的创神星采矿站（**37.78 AU**，
治理成本 ≈1.7/月、忠诚长期贴地）倒戈到中国，**同月**运输联盟对我宣战（倒戈带
`diplomacy.capture_delta = −25` 的关系打击）；
r148/r150 阋神星前哨、海王星轨道站同样自动归我（后者忠诚 0.36，最终又倒戈回去）。
控制面**没有 abandon / refuse / donate / raze 任何一片叶子**；`governance-loyalty.md` 里
「倒戈目标要治理得住」的过滤也仍是未做项。

- `[ ]` **`--abandon <city>`**（撤出：夷平自己的城 / 移交第三方 / 交还原主），
  至少给一个「拒绝接收倒戈」的 scope 叶子；否则玩家会被动继承一堆治理不住的边地，
  再被它们拖进战争（本局的运输联盟战争就是这么来的）。

## 5. 新单位/新城默认归 AI，玩家每段必须重新点名 —— **已解（见下）**

**事实**：新造出来的舰不在**玩家写的** diff 里 → 出厂即**默认 AI**（`spawn_ship` 只给它一条
`Control::inherit(Idle)` 的叶，没有说话 → 归属上溯 → `Auto`）。本局 r9 下水的北辰被 AI 派去
`follow` 一艘美国巡洋舰「落基」（远征送死流，而它的同级舰本该守家）；我每次分段续玩都要重新枚举
**当前活着的**舰名。而舰名会换代（长城 → 长城2、镇岳 → 镇岳3），**上一段的 diff 直接重放必然
指向不存在的实体**（本局吃到的那次静默丢弃是 `not_your_city`：我点名要投投资的城已经易主）。

**已解**（分支 `feature/control-tri-state`，详见 [`control-live-layers.md`](control-live-layers.md)）：

- ~~`[x]` **势力级「舰队默认指令」叶片** `default_ship_order{behavior, mode}`
  （`{"default_ship_order": {"behavior": {"type":"dock","body":"地球"}, "mode": "Player"}}`）：
  叶子没有说话（`Inherit`/缺叶）的舰——**包括刚下水的新舰**——归谁、干什么都在这里回答。
  r9 的北辰在今天就是「出厂即归你 + 直接去守地球」，一个字都不用点名。~~
  ⚠ **2026-10 删除**（[`blueprint-stance.md`](blueprint-stance.md)）：实测它不是"默认值"而是
  **全舰队接管开关**（写它 ⇒ 全舰队归属变 `Player` ⇒ 自动控制的 style/freight/contract 闸门
  全跳过、连自保撤退都不生效，而全舰队被钉死在同一条站桩指令上），而指令本身是**即时操作**、
  不该有势力级默认。上面那个**问题**（"新舰不在任何 diff 里，点名单舰会过期"）现在的答案是：
  **给这型舰一张带角色的设计图**（"这型舰是运输舰" ⇒ 它一出来就被派去跑集货路线），
  具体去哪仍旧**逐舰**现下。
- `[x]` **取值规则（活层的核心）**：AI 写回的叶值只是**流水**，不是指令；「继承」真的会上溯到
  高层值（⚠ 这条对**倾向三轴**仍然成立；**指令**链上 2026-10 起没有更高的一层了）。
  因此改**一个**势力级叶片 = 全舰队改主意（⚠ **只对倾向三轴**），「按我拥有的实体批量下发」的
  一部分需求消失了（`all_my_ships` / `--to-fleet` 划掉）：点名单舰只剩「例外」一种用途。
- `[x]` 顺带修掉同一根毛病的另一个入口：`colonize` 收尾不再把归属清成 `inherit`——
  玩家点名的殖民舰建完城不再被静默交还给系统。
- `[ ]` **剩余**：① `doctrine`/`kiting` 还是 `Ship` 上的裸字段（没有活层、没有舰队默认）；
  ② 「按舰级默认」（护卫舰守家 / 巡洋舰殖民）未做。两条都在
  `control-live-layers.md` §3/§4，**等用户裁决**。

## 6. 结构性叶片的所有权语义不明（`BuildingPatch` 没有 `mode`）

**事实**：`--control-schema` 的 `BuildingPatch` 有 `area/kind/resource/ship_type/structure/remove`
但**没有 `mode`**。实测两种命运并存：

- `area`（目标面积）**持久且会逐步铺开**：金星碳矿 1.5 → 22，deployed 每月 ≈+1.2，产量 0.75 → 1.35 ✔；
- `ship_type` **会被 AI 的舰队构成逻辑重估覆盖**：r0 钉的珠三角巡洋舰 r12 还在，但到 r36
  长三角/珠三角都已被 AI 改成 `battleship`；我在 r48 钉回 `cruiser`、r168 把海王星轨道站钉成
  `corvette`（r173 确实下水了护卫舰「破晓3」），**r174 同一船坞又下水一艘战列舰「长风3」**。

后果：玩家无法判断「这次结构性编辑下一回合还在不在」，只能逐回合观察反推。另注：`buildings` 只给 `city+kind+resource+area`（不带 `building` 下标）= **新建建筑**——本局 r168 给
海王星轨道站加水冰矿 12 面积，新建建筑 id 471 随后铺满 12 面积、月产 5.99 水冰，势力产量
从 0 回到 9.7。这条很有用，但同样没有任何文档/description 说明。

- `[ ]` **给结构性叶片补 `mode`**（`Player` = AI 不许覆盖该字段），或至少在 `--control-schema`
  的逐字段 description 里写明所有权（哪些字段会被 AI 重估、哪些持久）。
  → **`ship_type` 那一条的正解是 [舰船设计图](ship-blueprint.md)**：把「造什么」从建筑的一个
  裸字段升级成带三态的**设计图叶片**（AI 只重估 `Auto` 的设计图）。
- `[ ]` **把「无 `building` 下标 = 新建建筑」写进 schema description**（现在只能靠试）。

## 7. 失去的城市留下「幽灵权重」

**事实**：`invest_weights`/`build_weights` 在**你不再拥有的城**上仍保留条目。本局 r96 的
`--control` 里长期挂着亚特兰大、创神星采矿站、欧罗巴冰下港、奥林匹斯港、宁静海基地的条目
（`kind` 常是空串 `""`），条目数随战局**单调增长**（每打下一座城就多几条，永不回收）。
玩家分不清哪条是活的；更麻烦的是**一旦重新拿到那座城，旧权重会静默生效**。

- `[ ]` `--control` 默认只列当前持有的城（或给陈旧条目打 `"stale": true`），并按城 prune。

## 8. `--apply` 只报「丢弃」，不报「生效」

**事实**：全落地时 stderr **完全静默**（本局 7 次施政只有 1 次因创神星易主而报
`WARN_APPLY_SKIPPED`）。长局多段施政时，玩家缺少「这段国策在哪些城真的生效了」的回执；
与 §6 叠加尤其危险——**结构性叶片被 AI 覆盖是静默的**，agent 会带着「已下达」的错觉玩下去。

- `[ ]` 常态回执（`{"code":"APPLY_OK","applied":N,"touched":[…]}`），或让 `--index` 首行带本次
  apply 摘要；至少在 checkpoint 里记一条「上次 apply 落了哪些叶」。
  → 已先落了半条：**「写值即接管」的回执** `NOTE_APPLY_TOOKOVER`（`control.rs` 的
  `ApplyReport.took_over`），见 `control-live-layers.md` §2。**「哪些叶片真的落地」仍缺**。

## 9. `--round N` 的方向性歧义（可复现性的坑）

**事实**：`--round N` 是「自当前状态**再推进 N 月**」，不是「推进到第 N 月」。
`--start ckpt_r12 --round 36 --save ckpt_r36` 得到的其实是**第 48 月**的存档；本局前半程的存档
命名因此整体漂移，直到我从投影的 `round` 列才发现（`ckpt_r36.json` 实为 r48）。

- `[ ]` 拆成两个显式名字（`--months N` = 再推进 / `--until N` = 推进到第 N 月），
  或 `--save` 时把实际 `round` 回显到 stdout/stderr。

## 附 B：给下一个 agent 的两条硬经验（控制面之外）

1. **复垦废墟是唯一高速增长路径**（新城落地自带 300–500 人），但每座新城必须先配一艘守备舰——
   本局金星、奥林匹斯港、莫斯科都是「刚复垦就被夷平」。
2. **`--apply` 的 stderr 是唯一真相**：本局 r48 那次 `WARN_APPLY_SKIPPED` 就是在告诉我
   「你点的城已经易主」，而 stdout 与退出码一切正常。
