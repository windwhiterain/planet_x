# 思潮 → 角色：舰船倾向于运输还是战斗

> 本分支 `feature/ideology-role`（基于 `main` c7458f2）。用户裁决原文：
>
> * 「**由国家思潮决定自动控制下舰船倾向于运输还是战斗**」
> * 「**2 axis, 和平和殖民**」
> * 「**不要配置了，直接耦合思潮写死**」
> * 「运输/战斗是**动态调整**的，**而非固定**」
>
> 落地模块：`autocontrol::freight`（`freight_lean` / `freighter_quota` / `should_be_freighter`），
> 观察面 `src/projection.rs` 的 factions 三列。

## 1. 机制（四层，从硬到软）

`freight::should_be_freighter(state, config, fid, ship)` —— 纯函数，同回合同舰多次调用同结果
（骰子由 `(势力, 舰名, 回合, "role")` 派生、**不消费主 `Prng`**）：

1. **硬承诺**：正在执行承包单的舰、舱里有货的舰 ⇒ **必须是**运输舰。角色一改，那条线就再没人
   跑、那票货就烂在舱里。
2. **玩家表态**：这条轴归属解析为 `Player` ⇒ 用玩家的值，AI **一个骰子都不掷**（叶 → 舰队默认 →
   记录值这条链没变，`Control<bool>`，与另两条风格轴同形）。
3. **物理**：`freight_tonnage == 0`（没有推进模块 ⇒ 速度 0）的舰**运不了货**——派它去等于派一尊雕像。
4. **思潮驱动的配额 → 按票抽签**。

### 1.1 思潮 → 倾向（系数**写死**在 `autocontrol/freight.rs`，不进 config）

```
尚武度 martial = 1.0 × peace_military  +  (−1.0) × nature_colony      // LEAN_MILITARY / LEAN_COLONY
倾向   lean    = 2σ(−1.5 × martial)      ∈ (0, 2)                       // LEAN_GAIN
目标头数 quota = needed_freighters × lean                                // 需求 = 有积压的货栈数
```

* **两轴同权反号**：军国 ⇒ 尚武 ⇒ 少跑运输；殖民 ⇒ 要给远方殖民地送补给 ⇒ 多跑运输。
  于是「既军国又殖民」互相抵消（+1,+1 ⇒ 0）——扩张既要打仗也要补给，两股力量撞在同一个标量上。
* **中庸（尚武度 0）⇒ 倍数正好 1.0 = 旧硬定编的行为**。这条改动在世界的中位上是**行为中性**的，
  思潮只负责把倍数往两边推（实测 0.365 … 1.635）。
* **倾向乘在需求上**（不是取代需求）⇒ 不变量「**没有积压 ⇒ 配额 0 ⇒ 全员战舰**」保住。

### 1.2 配额 → 概率：**按票抽签**（与 `route_for` 同一条纪律）

```
缺口 gap = quota − 同侧头数            // 我不是运输舰时：还缺几条腿
超额 exc = 同侧头数 + 1 − quota        // 我是运输舰时：带上我超了几条腿
流量 flow = max(缺口/超额, 0) + 0.05 × 现状头数      // 第二项 = **轮换**（ROLE_ROTATION）
票   t_i = e^(效率加成 ÷ 0.5)          // 入伙按高效率；**退伍按低效率**（最差的船先走）
p_i      = clamp(flow × t_i ÷ Σ同侧票, 0, 1)
```

* `效率加成 = 1.5 × (本舰运力 ÷ 队内最大运力 − 1) ∈ [−1.5, 0]`（`ROLE_EFF_GAIN`，以**队内最大**
  为基准 ⇒ 尺度无关）。最好的船票最重，与最差船的票数之比 ≈ `e^(1.5/0.5)` ≈ **20 倍**。
  这就是旧「按运力排名取前 N」的**软版本**：偏好很硬、但**没有断崖**（真没人运货时战列舰照样
  会被抽中，遵 `AGENTS.md`「不设进不去的目标」）。
* **期望入伙数 = 缺口（+ 轮换量）**，不欠不过。
* **轮换**（`ROLE_ROTATION = 0.05`）：**入伙侧与退伍侧都加同一个 `0.05 × 现状头数`**
  ⇒ 期望「来的」与「走的」一样多 ⇒ **头数不动，换的只是「谁来干」**。
  没有它，配额处两侧概率都恰好是 0 ⇒ 谁去运货**一次定终身**（用户裁决：「运输/战斗是
  **动态调整**的，而非固定」）。
* 名单（分母）只算**掷得动的船**：玩家钉住的、舱里有货的、正在执行承包单的舰都不在名单上
  ——票不该投给动不了的人，否则期望入伙数会凭空少掉。

### 1.3 为什么不能「每艘舰各自掷一次身份」（实测踩过的坑）

第一版写成 `p_i = σ((缺口 ± 效率 − 迟滞带宽) ÷ 宽度)`：**所有舰同一回合看到的是同一个缺口**，
缺口大时**全舰队一起入伙**、下一回合又一起退伍。实测 12 艘舰、配额 4 时：200 个回合里
头数落在 3..=5 的回合数是 **0**——它在 0 与 12 之间两极震荡。
⇒ 改成抽签（概率分布 = 想要的比例）后：头数 198/200 回合**正好 4**，换岗 **0.005 次/回合**。

> 教训与 `freight-collection.md` §9 同源：**判据里不要出现被这个动作本身改变的量**；
> 而「每人独立掷一次 + 同一个全局量」会把独立的骰子**同步**成一次全量翻转。

## 2. 实测（`cargo test --lib probe_ideology_roles -- --ignored --nocapture`）

12 艘舰、4 处积压、200 回合：

| 思潮 | 倾向 | 配额 | 实际头数(均) | 换岗/回合 | 头数分布 |
|---|---|---|---|---|---|
| 军国 +1 | 0.365 | 1.46 | **1.52** | 0.467 | {0:18, 1:81, 2:81, 3:19, 4:1} |
| 偏军国 +0.5 | 0.642 | 2.57 | **2.51** | 0.513 | {1:17, 2:84, 3:75, 4:18, 5:4} |
| 中庸 0 | 1.000 | 4.00 | **3.97** | 0.518 | {2:6, 3:49, **4:99**, 5:40, 6:3, 7:3} |
| 偏和平 −0.5 | 1.358 | 5.43 | **5.38** | 0.709 | {4:27, 5:72, 6:70, 7:20, 8:2} |
| 和平 −1 | 1.635 | 6.54 | **6.47** | 0.829 | {5:28, 6:66, 7:66, 8:25, 9:5} |
| 殖民 +1 | 1.635 | 6.54 | **6.47** | 0.829 | 同上（两轴同权 ⇒ 与和平端同值） |
| 军国+殖民 | 1.000 | 4.00 | **3.97** | 0.518 | 与中庸逐列相同（抵消） |

* **平均头数贴着配额**（差 ≤ 0.06）⇒ 抽签那条纪律真的成立。
* **头数在配额上下 ±1 呼吸**（中庸：200 回合里 188 个落在 3..=5），而**人员一直在换**：
  换岗 0.52 条/回合 ⇒ 12 艘舰的舰队里**每条岗位平均 8 个回合换人**（够跑几趟来回），
  每艘舰平均 23 个回合轮到一次。这个量级是**轮换项**（0.05）与**缺口项**共同给的：
  轮换负责「一直在动」，缺口项负责「不越位」（头数一偏就被拉回来）。
* 入场与收场：单处积压（需求 1）**第 1 回合**就会出现第一条运输舰；积压清空后
  配额 = 0 ⇒ **第 1 回合**收回（超额是确定的、最后一条船的入伙/退伍概率被夹到 1）。

## 3. 长局实测（`probe_ideology_freight`，seed 7/11 × 400 回合）

每行：思潮 → 倾向 / 配额，与「运输舰头数均值 / 自运件数 / 雇人搬回件数 / 替人跑赚的抽成」。

* **多数势力的运输舰头数与配额对得上**（俄罗斯 7.66 vs 配额 17.8、中国 3.36 vs 11.4）
  ——注意配额是**期末**值而头数是**全程均值**，两者不同口径。
* **两个长局发现（都不是本机制的 bug，但值得下一轮处理）**：
  1. **思潮自己会饱和**：到 r400，9 个势力里有 6 个的 `nature_colony` 顶到 +0.98…+0.99
     （`peace_military` 几乎全为 0）⇒ 尚武度全都 ≈ −0.98 ⇒ 倾向全都 ≈ 1.63 ⇒
     **思潮不再区分势力**。这条改动只在思潮真有分化时才有分化效果；`step_ideology` 的
     殖民端驱动是不是太强，是另一件事（见 §5）。
  2. **世界本身在淘汰**：r400 时 9 个势力里 **7 个一艘舰都没有**。探针里「有 22 艘舰却几乎
     不派运输舰」的势力（星系矿业 seed 7）其实是 **r200 时 0 艘舰**、末期才重建舰队
     （首运在 r25，之后被打光）——不是「派不出人」。

## 4. 观察面（M5 那一半）

`src/projection.rs` 的 factions 表新增三列（`column_docs` 已写全）：

| 列 | 含义 |
|---|---|
| `freight_lean` | 思潮 → 集货倾向（倍数，中庸 = 1.0） |
| `freighter_quota` | 目标运输舰条数 = 需求 × 倾向（连续量） |
| `freighter_count` | 此刻**实际**在跑运输的舰数（含玩家钉住的/载货的/接单的） |

**`freighter_count` 与 `freighter_quota` 一比就能分开两件事**：「思潮不让跑」（配额低）与
「没人可派」（配额高但舰不够/动不了）。

## 5. 未做 / 下一轮

* **造舰动机的解耦（用户已下指令，尚未实现）**：
  * **造战斗舰的动机 = 敌对国与自己的实力差距**（用户裁决原文：「敌对国于自己的实力差距作为
    造战斗舰船动机」）——取代现在 `choose_next_class` 里那个 `if at_war && flagship { 0.6 }`
    的**布尔 + 常数**（`at_war` 是硬阈值，跨过开战线动机就整个翻转）。
    建议式：`威胁 = Σ_j 敌对度(关系_j) × (实力_j − 自己实力)`，再 `动机 = σ(威胁 ÷ 参考)`；
    军事实力**复用均势外交里的那把尺子**（不另编一个）。
  * **造货运船的动机 = 集货运力缺口**（积压 ÷ 航程折算的运力需求 − 自有运力），
    **与战时重构各占一个船坞**（互不淹没）。
  * `retool_shipyards` 现在**门口就写着 `if !faction_at_war { return }`**，且只在单一舰型 ≥60%
    时才动 ⇒ 和平期船坞造什么是**开局定死**的，「造货船的动机」根本不存在（谈不上耦合）。
* `own_ship_balance`（借出/抽手的余缺）**仍按 `needed_freighters` 算、不乘思潮**（用户裁决
  「先不动」）：所以军国的「富余」没有因为少跑运输而变大。
* 承运人侧也没有被思潮影响（受雇意愿仍是影子价格 + 缺口那套）。

## 7. 一条纪律（写给下一个改角色轴的人）

角色判据读的是**有效角色本身**（上一回合的结论）——那片叶**同时是记忆**。
所以：
* 它必须是**纯函数**（`assign_roles` 与更早的 `step_contracts` 各调一次，答案必须一致）；
* 骰子必须走 `derived_roll`（**绝不消费主 `Prng`**），否则「多造一艘船」会改掉世界后续的掷骰；
* 任何「现状」项都要**排除被这个动作本身改变的量**（这里用的是「我之外」的头数，
  入伙/退伍两侧共用它）。
