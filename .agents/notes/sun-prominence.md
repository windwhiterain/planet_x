# 太阳的日珥：从「一圈硬红环」到**世界空间插片**

> 状态 `[x]`（分支 `feature/glsl-files`，模块 `web/static/map3d/sun.js` +
> `web/static/shaders/px/sun/{photo,prom,corona}.*`）｜ 索引：[notes.md](../notes.md)
> ｜ 前文：[web-vfx-pipeline.md](web-vfx-pipeline.md)（那一轮的日冕体渲染）｜
> 量具：[shot-harness.md](shot-harness.md)

用户的目标是一张 **SDO/AIA 304Å 参考图**，原话两句：
- 「把太阳的日珥做成这个效果」
- 「重点是**纹理**，以及**日珥的形态** —— 日珥那种有很多**须须喷发出来**的感觉」

---

## 0. 结论先写

**日珥 = 世界空间的插片几何**（几千条细长的**曲面片**，沿长度弯出去）。
一切「在一个着色器里沿视线积分/解析求交」的做法都出不来须，原因见 §2。

## 1. 三条弯路（都真的走完了，别再走）

| 做法 | 为什么不行 |
|---|---|
| ① 等半径**球壳**（`SphereGeometry(R*1.012)` + 噪声） | 壳在几何上**没有径向厚度**：外缘永远等于轮廓线 ⇒ 只能读成「一圈均匀硬红环」，怎么调噪声都救不回来 |
| ② 并入日冕的**体积积分**（贴面密度场 × 沿视线累加） | 掠射时视线几乎与日面**平行**，穿过约 1.3 rad 的弧 ≈ **三十多根针的间距** ⇒ 积分把它们**平均成一层雾**。所以「加频率 / 改强度 / 换噪声」全都无效 —— 不是参数问题，是**积分这个动作**抹平了切向结构。（⚠ 这与上一轮修好的「欠采样」是两回事：那是采不到，这里是采太多） |
| ③ 每像素**解析求交**（把日珥当高度场球壳 `r = 1 + h(dir)`，射线找第一个落在壳内的点） | 形状确实出来了，但是 **2.5D**：没有真正的三维遮挡与视差，且「用哪一点当切向坐标」很难选 —— 用「最近点方向」时 `dot(u,t1) ≡ 0`（坐标系跟着点转 ⇒ 噪声退化成常量，画面变成一条光滑亮边）；用射线与壳的交点则要步进，最后还是回到②的老问题 |

**④ 插片（现在的做法）**：真几何、真遮挡、真视差、剪影天然正确，几千个 12 顶点的小网格，
`InstancedBufferGeometry` 一次 draw call。

## 2. 插片怎么搭的（`sun.js::buildPromCards` + `prom.vert/frag`）

- **一份单位网格**：`PlaneGeometry(1,1,1,4)`（宽 1、长 1、沿长度 4 段 —— 段数决定曲面片弯得顺不顺），
  配 per-instance 属性 `aDir`(根部方向) / `aSide`(片宽) / `aBend`(弯曲方向) / `aParam`(长, 宽, 弯曲量, 种子)。
- **形状全在顶点着色器里生成**：
  `p = aDir*(R−0.015) + aDir*(h·t) + aBend*(curve·h·t²) + aSide*(x·w·taper(t))`。
  根部**埋进日面 0.015**（不然掠射时片与球的切点会露出一条缝）；`taper = (1−t)^0.75` 收出尖头。
- **分布**：球面均匀 × `PROM_MAX = 12000`（按档位只改 `instanceCount`：ultra 12000 / high 5500 /
  medium 3000 / low 1200 / minimal 0 ⇒ 见 `TUNING.TIERS[].prom`）。长度是**长尾**
  `0.020 + 0.190·rnd^2.3`（太阳半径为单位），宽度 `0.0035 + 0.0095·rnd`（**必须细**，世界单位），
  方向再随机推 ±0.30（让针彼此不平行）。
- **确定性**：`mulberry32(0x5eed1234)`。**不要用 `Math.random`** —— 截图判据要可复现。
- **片元**（`prom.frag`）：横向剖面（中间实两边虚）+ 沿长度的**断裂**（两个频率的 vnoise +
  每片自己的相位 ⇒ 每根须的亮节位置都不同）+ 尖端散开；颜色根部亮橙 `(1.35,0.42,0.10)`、
  尖端深红 `(0.85,0.10,0.02)`。
- **`frustumCulled = false`**：插片铺满球面，three 从 `position` 算的包围球不含实例属性 ⇒
  不关剔除会整批消失（现象是「日珥时有时无」）。
- 材质：`AdditiveBlending` + `depthWrite:false` + **`depthTest:true`** ⇒ 发光体互相叠加，
  但会被**行星**挡住（这是②无论怎么调都拿不到的东西）。

### 两个必须有的衰减

1. **掠射衰减**（`prom.frag` 末尾）：`graze = 1 − |dot(viewDir, normalize(vWorld))|`。
   正对着看的针只是一个亮点、不该是一条长条；没有这一条时**整个可见半球都被针盖住**（像一只毛球），
   而 304Å 的盘面应该是**斑驳的表面**。
2. **盘面衰减**：`a *= smoothstep(0.25, 0.75, graze) * (0.20 + 0.80·graze)` —— 越靠盘心越淡。

## 3. 光球（`photo.frag`）：配色是**反解**出来的，不是看着调的

隔着 `ACES + exposure + sRGB` 三跳，照着屏幕调 HDR 会一直调歪（ACES 在 0.7 以上压得极扁、
红通道先饱和 ⇒ 「再亮一点」的结果是**丢掉颜色和结构**）。所以：

```
node scripts/shots/run.mjs --solve 195,62,10   →  HDR [0.5843, 0.0749, 0.0036]
```

五个锚点（`C_VOID/C_HOLE/C_MID/C_ACT/C_CORE`）就是从参考图的五档橙反解出来的，
**`TUNING.sunIntensity` 因此是 1.0（一比一）**，不再是「拍脑袋的 1.25」。

⚠ **`grade.mjs` 的矩阵存法**：GLSL 的 `mat3(a,b,c)` 把三个 vec3 当**列**填进去。
第一版照抄源码顺序当行用 ⇒ 整体转置。转置矩阵**正反算仍然自洽**（`--solve`/`--hdr` 互相
回代精确复原），所以自检发现不了 —— 只有把预测色和实机像素并排比才会显形
（预测 (186,73,15) / 实机 (197,62,47)）。**标定工具必须对着实机验一次，不能只看它自洽。**

### 实测（`sun-disk` 场景，1280×800，ultra）

| 量 | 参考图（SDO 304Å） | 现在 |
|---|---|---|
| 日面 meanRGB | (206,77,12) | (172,84,37) |
| 日面亮度 p10/p50/p90 | 0 / 98 / 147 | 23 / 96 / 145 |
| `whiteFrac`（白饼比例） | 0 | 0 |
| 背景 | ~0（纯黑） | ~22（**游戏自己的星云**，不是雾） |

> 数值只当**锚**用，别当目标函数：用户明确说过「你在追求颜色分布近似吗，这不是重点」。

## 4. 纹理：格点噪声的**方格纸**（顺手修掉的全局问题）

现象：日面放大是一片**小方块**（每块约 8 px，正好是 `p*SC` 里 SC=105 的格距）。
根因：`vnoise` 是**三线性插值的格点噪声**，等值线自带轴向方格；`fbm/ridged` 把几个八度
叠起来时所有格子**朝向相同** ⇒ 叠出来是一张方格纸。`ridged` 的 `n*n` 又把等值线锐化，
所以它最明显。

修法（两层）：
1. **八度之间换格子朝向**：`px/noise/rot.glsl` 里那个正交矩阵（绕 (0.30,0.70,0.6481) 转 47°），
   `fbm`/`ridged` 每进一个八度乘一次。单独一个文件是为了 `photo.frag` 同时 include
   `fbm` 与 `ridged` 时不重复定义常量。
2. **换成梯度噪声**：`px/noise/perlin.glsl` 里的 `pnoise/fbmP/ridgedP`（12 个固定方向的
   Perlin，每角点仍只 1 次 hash ⇒ 与 vnoise 同阶）。**太阳用的是梯度噪声**；
   行星/云/星云仍在用 `fbm/ridged`（value 版）—— 换成梯度噪声会改它们的外观，属于**另一个
   需要单独验收的任务**（`sun-disk`/`earth` 场景已经具备验收条件）。
3. 光球的八度**封顶 4**（`sun.js`）：uFbmOct=7 时最细一层是 105·2.13⁶ ≈ 9800 周期/弧度
   ⇒ 屏幕 0.1 px，纯属亚像素闪烁（观感是「砂纸」而不是米粒）。

## 5. 日冕（`corona.frag`）：本轮只做减法

- 删掉粗积分里的**厚弧道** `arcade`（σ=0.13R ≈ 0.83 世界单位，而 dt ≈ 2.8 ⇒ 壳比步长还薄，
  采到多少全凭运气；更要命的是它正穿日面时也有 ~10 世界单位的路径 ⇒ 把标定好的日面
  均匀加亮 ~0.8 HDR，实测洗成 (249,197,155)）。
- `uFalloff` 2.6 → **4.2**（1.5R ⇒ 0.18、2R ⇒ 0.054、3R ⇒ 0.010：远景有晕、近景不糊）。
  ⚠ 别再靠改这个指数救雾 —— 2.6 那版的雾**另有主因**（上面那条 + 色球壳太厚），都已单独修掉。
- 色球/日珥的**全部**代码从 `corona.frag` 里删掉（`uChromo` 一并删）—— 它们现在是几何。

## 6. 顺手修掉的两个真 bug

- `postfx.js::setTier`：`const on = TUNING.postfx !== false;` —— `?tune=postfx:0` 走的是
  **数值**覆盖（`Number('0')` = 0），而 `0 !== false` 恒真 ⇒ 这条逃生门一直是**哑的**。
  另外 `index.js::init` 首帧**从没调过** `post.setTier(tier)`（`createPostFX` 只看 tier），
  所以加载时那一次也是哑的。两处都改了（用真值判断 + 首帧补一次）。
- `TUNING.coronaOn`：新增的**体积层总开关**（与 `postfx` 同口径的 tune 逃生门），
  用来把「光球 / 体积 / 插片」分开做 A/B（`--query 'tune=postfx:0,coronaOn:0'`）。

## 7. 未做 / 下一步（按价值排）

- `[ ]` **针的形态还能再走一步**：现在每片是「一条带子」，真实日珥是**弧（loop）**——
  两端都落在日面上、中部拱起。做法：把 `aBend` 的二次曲线改成「两端回到 r≈1」的弧
  （顶点着色器里 `−aDir·(h·t²)` 让尖端往回弯），再让一部分插片（比如 20%）用这个模式。
  **这一条最值得做**：参考图里的日珥主体是弧，须只是它的足点。
- `[ ]` **盘的纹理**：现在大暗区偏「大块」。参考图的典型日面是**网状（亮格 + 暗沟）**，
  暗区只占 ~20%。可以加一层「细暗沟网络」（`ridgedP` 的高值当暗线）再拉开一次对比。
- `[ ]` **插片数量与档位的性能验收**：12000 片在 3060 上没问题（`debug().frameMs` 可看），
  但**核显**（`high` 档）还没量过；`PROM_MAX` 的分布也只按「日缘带 ≈ 球面的 1/10」估过。
- `[ ]` 插片的**尖端**在放大后能看出是「锥形带子」；要更真需要每条带子再细分 2 段
  （`PlaneGeometry(1,1,1,6)`）并让 taper 更陡。
- `[ ]` 行星/云/星云是否也切到 `fbmP/ridgedP`：需要单独做一次视觉验收（`earth` 场景已就绪）。
