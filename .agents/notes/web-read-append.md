## 0. 一句话

**残差不再是折叠桶**：`specview.js` 把「没被任何一列认领、也没显式 omit 的字段」按
**引擎字段序**追加成**普通 `<th>/<td>`**（表格）与**普通 `.sv-sheet-row`**（卡片里的行），
列头就是字段名、走与手工列**同一条** `ctx.tip` 查词链；`其余` 列、`▸N` 按钮、
「其余字段（N）」那条渲染路径**整条删除**，`sv-th-res` / `sv-residual` / `sv-residual-box`
三个类名一并清掉。**铁律 R 没退化**：引擎加一个字段 ⇒ 下一帧它就是一列，前端一行不改；
`omit` 仍是唯一能藏数据的方式，而界面会把省略明说（`omitLine`）。

## 1. 顺序来源（为什么是这个）

追加列的**顺序 = 记录自身的键序**（`Object.keys(rec)`）——它就是 **serde 按结构体声明序**
写出来的键序（`serde_json` 开了 `preserve_order`，见 `Cargo.toml`），与 `--nouns` 里
state schema 的 `properties` 顺序**同源**（同一个 `struct` 声明）。

**没有选投影 `schema.json` 的 `columns` 顺序**，因为它描述的是**另一张表**：实测
`factions` 投影列有 `round`/`capital_body`/`mond_*` 这些**投影侧派生列**，却**没有** `颜色`；
`ships` 投影列**没有** `坐标`/`攻击历史`。读面渲染的是 `/api/state` 的模型 dump，
拿投影列排序会把它排成投影的顺序（而且还得为"不在投影里的字段"另想一个位置）。

`g4_spec.py` §8 拿**两份引擎出口**互相钉：`--nouns` 的 `state.definitions.<Struct>.properties`
顺序 vs 真记录的键序（同源 ⇒ 必须一致），并且 §8d 逐表对投影真实列。

## 2. 值怎么渲染（不许 `[object Object]`，也不许只剩 `{4}`）

追加字段的「列声明」是**渲染时现造**的（`autoCol(key, v)`）：只有字段名 + 一个按**值类型**
挑的通用格式化器 —— 对象 ⇒ `map`（键值全印出来）、数组 ⇒ `list`、布尔 ⇒ `bool`、
数字 ⇒ `num`（与手工数字列同一个格式）。实测（seed 42 / 40 回合，势力页）：

| 追加列 | 值类型 | 印出来 |
| --- | --- | --- |
| `好战度` | number | `0.6` |
| `思潮` | object（四条轴） | `和平↔军国 0.5 · 科学↔技术 0.5 · 人民↔精英 0.3 · 自然↔殖民 0.6` |
| `关系` | object（八家） | `中国 -14.99 · 俄罗斯 -9.84 · 无国界科学组织 0.94 · …` |
| `本土半径`/`本土攻击倍率`/`本土再生加成`/`名声` | number | `6` / `0.85` / `0.02` / `1` |

`.sv-td-auto` 用**换行**显示（不是省略号截断）——「看都看不见」正是这次要修的。

## 6. 没做 / 拿不准

* **`events` 表的 30 个追加列里有 11 个弹不出解释**（`attacker`/`shipper`/`a`/`b`/`cargo`/
  `carrier`/`faction`/`how`/`prev_owner`/`reason`/`seeded_ship_class`）：它们是
  `GameEvent`（`#[serde(tag="type")]` 枚举）的**变体字段**，Rust 侧本来就没写 `///`。
  要给它们写注释是**引擎文档**的活（会牵动 §5b 文档对账），不在本步范围内——判据 §8c
  把这类 ASCII 槽位名**如实记账**，不假装它守住了。
* **`events` 表的追加列是按「各行键的并集」算的**（31 个字段里 30 个是追加），所以单行上
  大部分格子是 `·`。这是「一条也不藏」的直接后果（事件是同一个枚举的不同变体）；若嫌宽，
  那要改的是**声明**（给事件表挑列 / 写 omit 并说明理由），不是把追加机制再藏回去。
* 分组表（舰队/城市按势力分组，9 张表）每个分组各有一份表头，所以同一组追加列会重复出现
  9 次——列集**来自整张表**（不是每组各算一次），因此组与组之间不会漂。
* 追加列的**顺序在异构行之间**是「按行序 × 各自声明序首次出现」的合并；同一实体类型
  （99% 的情况）它就是声明序。多态来源（`@post.decisions.blueprints[*]` 这种）目前每帧是
  同构的，没有实测到反例。
* `web/static/views.json` **一个字都没改**（用户没要求调整声明；`符号`/`颜色`/`阵营倾向`
  仍由 `faction-table` 声明不看——那是**声明**的选择，界面上把省略明说了）。

### 8.1 一句话

左栏那 7 个页签不变，但**每一页不再是一张宽表**：`layout: "layers"` 的视图是**两层** ——
外层是「一行一个项目」的紧凑总览（名字 + `brief` 声明出来的少量关键指标），点一行进内层，
内层是那**一条记录**的「名字 → 值」逐条行（`sheetOfRecord`：声明列按**人工顺序**在前，
引擎给的其余字段**追加在末尾成普通行**）。顶部有面包屑（`势力 › 中国`，**点根那一节也能返回**）
与明确的「← 返回总览」；返回时把进内层前的滚动位置还给你。

**铁律 R 的落点从"表格的追加列"换成"详情层的追加行"**（机制一个字没退：还是
`residualKeys` 现算的集合差），所以第 8/9/10 步的守卫一条都没丢（§8b/§9 一个字没改，
§8c/§8e 照旧绿，§8a 只换了它守的那一层）。

### 8.2 声明形状（新）

```json
{ "id": "faction-table", "title": "势力概况", "mount": "panel",
  "layout": "layers",                                  // ← 外总览 + 内详情
  "source": "@state.factions[*]", "key": "势力",
  "brief": ["实力占比", "状态", "城", "舰"],            // ← 外层总览行放哪几条**声明列**
  "select_kind": "faction",
  "order": [{ "by": "@post.power_share.${势力}", "dir": "desc" }],
  "columns": [ /* 详情层的人工顺序（读行 + 控制行同一条行序）—— 一个字没改 */ ] }
```

* **`brief`**：总览行显示哪几条关键指标。每一条要么是本视图某条列的 `path`、要么是它的
  **显示名**（`label`）。**前端不手抄字段清单** —— `g4_spec.py` §10a 逐条静态验「命中」，
  命中不了（或命中的是控制行）就红。指标之外的字段不进总览行（那是"一屏塞得下"的克制），
  但**全部字段都在详情层**。
* **`single`**（非空**理由**）：只有一条记录的视图（`战局`、`价格`、`全局作用域`）**直接显示
  详情**，不为它造一个只有一行的列表再点进去。理由必须写（空白 = 拿"就一条"当逃生门 ⇒ 红），
  而且**这句话会被真渲染复验**（真世界里真有一条以上记录 ⇒ 红，见 §10b）。
* **旧骨架在 panel 视图里一个都不许剩**（`table` / `timeline` / `cards` ⇒ §10a 红）。
* `mount: select` 的卡片（底栏"选中读面"）**本来就是详情层** ⇒ 不许再声明 `brief` / `layers`。

### 8.4 判据（实测原文见下）

* **§8a（换落点）**：`追加完整性（**详情层**）：15 张读面表/卡片（216 条记录、195 个引擎字段）上
  声明列(87) ∪ 追加行(103) ∪ 声明不看(5) == 全部引擎字段` —— 口径与第 8 步**逐字相同**，
  只是守的那一层改名了（`_append_probe.js` 那边一行逻辑都没动）。
* **§10a 分层声明（静态）**：`11 个 panel 视图是 layout: layers（共 34 条 brief，每条都命中
  本视图的一条读列）、3 个写明了 single + 非空理由，旧骨架 table/timeline/cards 在 panel 里 0 处`。
* **§10b 每个总览行都能进详情层（真渲染）**：`11 个分层视图的 140 行，逐行「点进去 → 面包屑
  末节 == 这一行的名字 → 点「← 返回总览」→ 外层行数恢复」全部通过；single 的视图确实 ≤1 条
  记录；3 个空来源合成场景（{}/[]/一条记录的对照）一行都不多不少`。
* **§10c 详情层的字段集合 == 该实体的全部字段（真渲染）**：`140 条记录的详情层上，
  (声明认领(613) ∩ 字段) ∪ 屏幕上的追加行(753) ∪ 声明不看(27) == 全部字段(1393)`，
  且**追加行逐字等于前端自己的 `residualKeys`**、写面控制行 186 条也都在这一层。
  **与 §8a 不重复**：§8a 查**声明求值**（导出的纯函数），§10c 查**屏幕上真有的行** ——
  注入 ㊳ 让详情层不再追加残差行时 §10c 红、§8a **仍绿**，这就是"两条不是同一条"的证据。

### 8.7 没做 / 拿不准

* **`renderTable` / `renderTimeline` / `renderCards` 留在 `specview.js` 里**（通用布局仍然存在，
  只是声明里没有一个 panel 视图再用它们）。理由：§8b/§9 的追加接线标记
  （`sv-th-auto` / `sv-td-auto` / `autoTh`）长在表格那条路径上，**删掉它们等于悄悄削弱那两条
  守卫**（用户裁决"不许把上一步的机制一起删掉"）。代价是留了一段**声明层已不可达**的代码 ——
  真正的"左栏没有宽表"由 §10a 静态钉住（panel 视图的 layout 不许是 table/timeline/cards）。
  拿不准的点：下一步要收掉这段死代码，就得同时把 §8b/§9 的标记集合改成详情层的那几个
  （`sv-sheet-row-auto` / `residualCols` / `autoSheetRow`），那是一次**量具口径的改动**，
  留给用户裁决。
* **`events` 的 `brief` 只能放 4 条固定载荷列**（`舰`/`城`/`攻击方`/`合同号`）：事件是同一个
  枚举的不同变体，没有"每条都有的标识字段"。所以很多行会出现 `—`（声明过的格子永远在，
  没有就是 `—`）。要更好只能给事件加一个**计算出来的标题**（那要引擎发 `headline`），
  不在本步（第 10 步的笔记 §10.6 已记过同一件事）。
* **`offers` 的 `key` 是 `seller`，不唯一**（同一卖家可以有好几张单）：外层总览照样一行一条，
  靠 `brief`（货/量/要价）区分；层状态按 key 记 ⇒ 同名记录会打开**第一张**。彻底修要给
  offers 一个复合身份（引擎侧的活），本步没动。
* **`wrap()` 的空对象修复**是实机发现的真 bug（`@post.haul_steps` 开局 `{}` ⇒ 幽灵行）。
  `sheet` 布局也受影响（空对象来源现在显示"这一帧没有数据"而不是一张空表）——这是**行为
  改变**，我判断它更诚实，但记在这里备查。
