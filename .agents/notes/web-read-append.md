## 0. 一句话

**残差不再是折叠桶**：`specview.js` 把「没被任何一列认领、也没显式 omit 的字段」按
**引擎字段序**追加成**普通 `<th>/<td>`**（表格）与**普通 `.sv-sheet-row`**（卡片里的行），
列头就是字段名、走与手工列**同一条** `ctx.tip` 查词链；`其余` 列、`▸N` 按钮、
「其余字段（N）」那条渲染路径**整条删除**，`sv-th-res` / `sv-residual` / `sv-residual-box`
三个类名一并清掉。**铁律 R 没退化**：引擎加一个字段 ⇒ 下一帧它就是一列，前端一行不改；
`omit` 仍是唯一能藏数据的方式，而界面会把省略明说（`omitLine`）。

## 1. 顺序来源（为什么是这个）

追加列的**顺序 = 记录自身的键序**（`Object.keys(rec)`）——它就是 **serde 按结构体声明序**
写出来的键序（`serde_json` 开了 `preserve_order`，见 `Cargo.toml`），与 `--nouns` 里
state schema 的 `properties` 顺序**同源**（同一个 `struct` 声明）。

**没有选投影 `schema.json` 的 `columns` 顺序**，因为它描述的是**另一张表**：实测
`factions` 投影列有 `round`/`capital_body`/`mond_*` 这些**投影侧派生列**，却**没有** `颜色`；
`ships` 投影列**没有** `坐标`/`攻击历史`。读面渲染的是 `/api/state` 的模型 dump，
拿投影列排序会把它排成投影的顺序（而且还得为"不在投影里的字段"另想一个位置）。

`g4_spec.py` §8 拿**两份引擎出口**互相钉：`--nouns` 的 `state.definitions.<Struct>.properties`
顺序 vs 真记录的键序（同源 ⇒ 必须一致），并且 §8d 逐表对投影真实列。

## 2. 值怎么渲染（不许 `[object Object]`，也不许只剩 `{4}`）

追加字段的「列声明」是**渲染时现造**的（`autoCol(key, v)`）：只有字段名 + 一个按**值类型**
挑的通用格式化器 —— 对象 ⇒ `map`（键值全印出来）、数组 ⇒ `list`、布尔 ⇒ `bool`、
数字 ⇒ `num`（与手工数字列同一个格式）。实测（seed 42 / 40 回合，势力页）：

| 追加列 | 值类型 | 印出来 |
| --- | --- | --- |
| `好战度` | number | `0.6` |
| `思潮` | object（四条轴） | `和平↔军国 0.5 · 科学↔技术 0.5 · 人民↔精英 0.3 · 自然↔殖民 0.6` |
| `关系` | object（八家） | `中国 -14.99 · 俄罗斯 -9.84 · 无国界科学组织 0.94 · …` |
| `本土半径`/`本土攻击倍率`/`本土再生加成`/`名声` | number | `6` / `0.85` / `0.02` / `1` |

`.sv-td-auto` 用**换行**显示（不是省略号截断）——「看都看不见」正是这次要修的。

## 3. 删掉了什么

* `specview.js`：`residualCell`（`其余` 列那一格）、`renderResidualInto`（折叠块重画）、
  表头那个 `el('th','sv-th sv-th-res','其余')`、`sheetOfRecord` 里的 `▸ 其余字段 N 项` 块；
  `limitNote` 的措辞从「其余 N 条未显示」改成「还有 N 条未显示」（同一个词，换个说法）。
* `style.css`：`.sv-th-res` / `.sv-residual` / `.sv-residual-box` 删掉；新增
  `.sv-th-auto` / `.sv-td-auto` / `.sv-sheet-row-auto`（虚线分隔，一眼看出"左边是整理过的、
  右边是自动追加的"，但**它就在表里**）。
* `app.js`：那条底栏说明改成「没被声明的字段自动追加在每行/每列后面」。

## 4. 判据（`play/tests/g4_spec.py` **§8**，四条）

| 判据 | 口径 | 实测（seed 42 / 40 回合） |
| --- | --- | --- |
| §8a 读面覆盖 | 每张读面表/卡片：`声明列 ∪ 追加列 ∪ 声明不看列 == 该记录的全部引擎字段` | **14 张表/卡片 / 207 条记录 / 184 个字段**：声明 79 + 追加 100 + 不看 5 = 184；`phantom`（声明了记录上没有的字段）与 `omit` 写了不存在的字段都 0 |
| §8b 没有折叠桶（静态） | `specview.js` 的**代码**（去注释）里 `其余`/`sv-th-res`/`sv-residual`/`residualCell`/`renderResidualInto` 一个不许出现；`sv-th-auto`/`sv-td-auto`/`sv-sheet-row-auto`/`residualCols`/`autoTh` 一个不能少 | 0 处桶 + 5 个接线标记齐全 |
| §8c 追加列的名词覆盖率 | 中文追加字段名必须查得到解释（走与手工列同一条查词链）；ASCII 槽位名如实记账 | **42 个中文追加字段全部命中语料**；引擎内部 ASCII 槽位 43 个（`events` 的 `attacker`/`shipper`/`a`/`b`…，枚举变体字段，本来没有中文名词）⇒ 那几条 hover 弹不出解释，是**引擎缺命名**，不是本机制缺接线 |
| §8d 投影对账 | `(声明 ∪ 追加 ∪ 不看) ∩ 投影列 == 投影列 ∩ 实体 schema 字段`（`--index` 的 `schema.json`） | **7 张读面表 / 169 个投影真实列 / 71 个在实体 schema 里**：`factions 12==12`、`ships 16==16`、`cities 7==7`、`bodies 1==1`（`events` 跳过：`GameEvent` 是 oneOf 枚举、没有 `properties`） |

**为什么口径不是「== 投影列」**：投影自己有派生列、也真的丢字段（`factions` 不发 `颜色`、
`ships` 不发 `坐标`/`攻击历史`）——能对的是**交集**（两边都认的那些字段）。这一步既是
用户要的「把每张声明的表与投影真实列做集合对账」，也顺手把「投影发了而读面看不见」钉死。

### 判据怎么保证**不是恒真**（`_g4_negative.py` ㉙㉚㉛）

* **㉙ 把 `residualCols` 剪成 `return []`**（= 追加路径坏了）⇒ §8a **自己红**：
  「situation：没被任何一列覆盖 `[cities, decisions, factions, haul_steps, market_offered,
  market_price, market_trades]`」（同时 §8d 报「投影发而读面看不见」）。
* **㉚ 把类名改回 `sv-th-res` + 把「其余」塞回代码** ⇒ §8b 红。
* **㉛ 把 `faction-table` 的 `资源` 那一列删掉**（= 未声明）⇒ 覆盖判据**不红**（**这是对的**：
  未声明 = 自动追加，用户要的正是这个），但判据文本必须**指出**这一列现在只能靠追加：
  同一张表的计数从「声明3+追加7+不看3=13」变成「声明2+追加8+不看3=13」，而且 `资源` 落在
  追加串里**引擎字段序**的位置上（记录里 `资源` 排在 `名声` 与 `关系` 之间）。

### 判据为什么走 Node（`play/tests/_append_probe.js`）

`residualCols` / `claimedKeys` / `omittedKeys` 的真值只在 `specview.js` 里。判据自己抄一份
口径 = 迟早和前端漂开（本仓吃过一次：`g4_spec.py` §5d 记的那个 `owner` 行缺口）。
所以 §8a 用 Node 把 **`specview.js` 原样加载**（`global.window = {}` + `require`），
调它自己的 `expand` / `claimedKeys` / `omittedKeys` / `residualCols` / `autoCol` / `format`，
拿输出和引擎的真记录对账；Python 侧只留一份**镜像**，其唯一用途是：Node 不在时降级
（判据文本里明说降级），并且**只要 Node 在就验一次「镜像 == 真代码」**（口径只有一份）。

## 6. 没做 / 拿不准

* **`events` 表的 30 个追加列里有 11 个弹不出解释**（`attacker`/`shipper`/`a`/`b`/`cargo`/
  `carrier`/`faction`/`how`/`prev_owner`/`reason`/`seeded_ship_class`）：它们是
  `GameEvent`（`#[serde(tag="type")]` 枚举）的**变体字段**，Rust 侧本来就没写 `///`。
  要给它们写注释是**引擎文档**的活（会牵动 §5b 文档对账），不在本步范围内——判据 §8c
  把这类 ASCII 槽位名**如实记账**，不假装它守住了。
* **`events` 表的追加列是按「各行键的并集」算的**（31 个字段里 30 个是追加），所以单行上
  大部分格子是 `·`。这是「一条也不藏」的直接后果（事件是同一个枚举的不同变体）；若嫌宽，
  那要改的是**声明**（给事件表挑列 / 写 omit 并说明理由），不是把追加机制再藏回去。
* 分组表（舰队/城市按势力分组，9 张表）每个分组各有一份表头，所以同一组追加列会重复出现
  9 次——列集**来自整张表**（不是每组各算一次），因此组与组之间不会漂。
* 追加列的**顺序在异构行之间**是「按行序 × 各自声明序首次出现」的合并；同一实体类型
  （99% 的情况）它就是声明序。多态来源（`@post.decisions.blueprints[*]` 这种）目前每帧是
  同构的，没有实测到反例。
* `web/static/views.json` **一个字都没改**（用户没要求调整声明；`符号`/`颜色`/`阵营倾向`
  仍由 `faction-table` 声明不看——那是**声明**的选择，界面上把省略明说了）。
