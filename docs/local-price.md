# 局部价格实验

## 0. 一句话

**仓库只定价，市场自动挪货，钱在部门手里。**

没有买卖申报，没有逐地方账本，没有指数回退，没有学习器。三样东西各管一件事：

| 层 | 只管 | 不管 |
|---|---|---|
| **仓库** | 挂价、目标水位、库存 | 申报方向、成交、货币 |
| **市场** | 按挂价差把货从低价挪到高价 | 货币、方向申报、数量上限 |
| **部门** | 按自己仓库的挂价买卖、遵守现金预算 | 定价 |

决策链是单向的：仓库挂价 → 市场挪货 → 部门按价交易。**没有任何决策读指数。**

历史实验记录（旧机制、被推翻的方案、逐条实测数据）在
[`local-price-history.md`](local-price-history.md)。

## 2. 机制

### 2.1 仓库：有界水平价格律 + 一阶低通

```text
比值  = ln(库存 / 目标)          （夹在 ±40）
映射价 = 价格基准 · exp(−κ · tanh(比值))
挂价  = L · 上一轮挂价 + (1 − L) · 映射价
```

- **为什么是水平律而不是速率律**：速率律把价格当成对 `库存/目标` 的积分，于是价格与库存构成两个串联积分器，必然零阻尼振铃（旧机制实测挂价跑到 `2.6e-9` / `4.0e8`）。水平律是**无状态的有界映射**，价格环的"记忆"就是那个积分器本身。
- **κ** 决定带宽：`tanh` 把映射价夹在 `基准 × [e^{−κ}, e^{κ}]`，所以价格**在构造上有界**。
- **L** 是承重件，不是点缀。低通把"仓库读自己的价"这个 1:1 回路（S2 之后增益是 1，不再有地方平均）压住。实测 L = 0 在参数空间的任何角落都振荡；L = 0.8 是稳定区。
- 目标一旦为 0 或非有限，取 1.0 兜底，价格仍然是有限正数。

### 2.2 仓库：目标按未满足的意愿慢速调整

```text
unmet = 意愿 − 实际取走
目标 += rate · unmet            （夹在 [下限, TARGET_CAP]）
```

`意愿` 是**把库存行整条拿掉**再解一趟结算得到的"货架无限时会取走多少"，
但那一趟额外叠了一条**现金行**（见 §2.4）：只有产能约束时欲望是单调无界的
（实测目标只涨不落、严格正比于速率、一路顶到上限）。价格高 ⇒ 买得起的篮子数
掉下来 ⇒ 意愿能落到实际以下 ⇒ **规则的第二半（满足了就降目标）才可达**。

`rate = 0` 就是关掉它，目标恒为下限。

### 2.3 市场：纯势流

```text
对每个商品、每一对仓库：
    卖方 = 挂价低的一方，买方 = 挂价高的一方      ← 方向只由挂价比较得出
    价差 = ln(买价 / 卖价)                       ← 由构造 ≥ 0
    势   = tanh(价差 / flow_scale) · 关系
    流量 = 卖方库存 · min(1, Σ势) · 势 / Σ势
```

- **没有申报方向**：仓库挂出去的是**库存本身**（一个事实），方向由市场算。
- **没有数量上限**，除了物理上的"卖方最多把自己那份库存出完"。
- **不涉及货币**。
- 挂价相同 ⇒ 势为 0 ⇒ 不成交（没有价差就没有势）。

这条规则取代了旧的"申报量符号门禁 + 软成交"：旧门禁是个结构性禁令，把"一个仓库同时对甲卖、对乙买"也一起禁掉了；而软成交在方向改由挂价给出之后会与价格滞后冲突（价格刚翻向时被判错向 ⇒ 势为 0 ⇒ 不成交，实测成交量掉三分之一）。

### 2.4 部门：直接与自己的仓库交易，受现金约束

```text
结算：成本   = Σ 仓库挂价 · 部门提货量        （买消费，付钱）
      收入   = Σ 仓库挂价 · 部门产出         （卖产出，收钱）
      余额  += 收入 − 成本
```

消费的**预算约束**是结算里的一条现金行 `Σ 一篮要价 · x ≤ 余额`；余额为 0 时不加这一行，
消费只受存量约束。

货币是**存量**（跨轮累积），所以还需要两条政策把它关住：

- **数量控制** `normalize()`：每轮把总量按比例拉回 `GRANT × 部门数`。
  结算是净创造货币的（部门把产出卖给**不持钱**的仓库），不控制的话购买力无界增长
  （实测 `dealt` 从 2075 涨到 8316、`cons` 从 653 涨到 876，一路往上跑）。
  按比例缩放**保持相对份额**，所以"存量"性质仍在。
- **转移支付** `transfer(rate)`：每轮把余额按比例拉向均值。总量守恒（纯再分配），
  管的是"纯消费部门手里有没有钱"。实测把逐部门余额控制在均值 ±10% 以内。

### 2.5 结算：内点法，单一行表

部门用原始-对偶内点法解 `max Σ w_p·x_p^θ`。约束按**行**组织：

| 行 | 系数 | 上限 | 障碍权重 |
|---|---|---|---|
| 商品行（每种有货的商品一条） | `(投入 − 产出) / 存量` | 1 | 1 |
| 预算行（产能、现金） | `占用 / 上限` | 1 | `BOX_WEIGHT = 1e-4` |

预算行给更小的障碍权重，是因为它**不是存量**：同样的权重会让生产系统性地
跑在产能的 ~90%（实测环流 4 → 3.605）。拆开之后 3.999582。

`willingness`：生产政策 = 每篮净货币价值；消费政策 = `motive ÷ 一篮要价`
（需求弹性就落在这里——只有 `motive` 时需求对价格完全无弹性）。

## 3. 参数与默认值

| 参数 | 默认 | 位置 | 作用 |
|---|---|---|---|
| `--price-curvature` κ | 1.0 | `Warehouses::DEFAULT_PRICE_CURVATURE` | 挂价对库存比值的陡度，同时是带宽 `e^±κ` |
| `--price-inertia` L | 0.8 | `DEFAULT_PRICE_INERTIA` | 挂价一阶低通。**承重件**，0 = 振荡 |
| `--target-rate` | 0.01 | `DEFAULT_TARGET_RATE` | 目标对未满足意愿的响应。0 = 关掉 |
| `--flow-scale` | 0.5 | `Market::DEFAULT_FLOW_SCALE` | 势流的价差尺度 |
| `--grant` | 1000 | `local_price::GRANT` | 部门开局货币 = 货币总量目标 |
| `--transfer` | 0.5 | `Departments::DEFAULT_TRANSFER` | 转移支付速率 |
| `--barrier` | 0.1 | `settlement::BARRIER` | 内点法障碍强度 |
| `--curvature` | 0.5 | `settlement::CURVATURE` | 边际效用曲率 `u = x^θ` |
| `--capacity` | — | 场景 | 部门产能预算 |
| `--specialty` | 1.0 | 场景 | 各部门对自己那一层的产出乘数 |

**量纲提示**：`--grant` 是**真实余额**的旋钮。实测 `grant ≥ 1000`（约 55 元/单位轮流量）
以上消费就饱和在物理约束上；低于这个量级，需求被现金憋住，货会堆在仓库里
（实测总库存 314341 → 627551 一路涨）。

## 4. 验收读数

### 4.1 跨种子 / 长跑

```bash
cargo run -q -p planet_x --bin local_price -- --scenario modern --capacity 12 --specialty 2 -n 800 --every 400 --json
```

`modern --capacity 12 --specialty 2`，800 轮：

| 轮 | 消费 | 成交 | 指数极差 | 总库存 | 货币 [最低, 最高] | 结算失败 |
|---|---|---|---|---|---|---|
| 400 | 825.56 | 793.53 | 3.355 | 807.1 | [896, 1091] | 0 |
| 800 | 798.02 | 733.43 | 3.250 | 747.7 | [899, 1090] | 0 |

- 模型现在是**确定性**的（见 §5.2），所以"跨种子分布"退化成单点，改为看 r400 vs r800 的差。
- 总库存 1600 轮无趋势（旧机制下一产库存线性涨到 147 万）。

### 4.2 质量守恒

```bash
cargo run -q -p planet_x --bin local_price -- --scenario modern --capacity 12 --specialty 2 -n 6 --every 1 --json
```

逐轮残差 `Δ库存 − (产出 − 消费)` ≈ `1e-4`，通量 ~900/轮 ⇒ 浮点噪声量级。

### 4.3 货币

逐部门余额在均值 ±10% 以内（`money_min` / `money_max` 见 JSON），总量恒等于
`GRANT × 部门数`。

### 4.4 测试

```bash
cargo test -p planet_x --lib
```

84 passed / 0 failed。覆盖：挂价律的有界性与惯性、目标规则的双向性与上下限、
指数是挂价几何平均、势流的方向/反对称/零和/无中生有/长跑有界、
结算的份额与产能约束、现金行、货币数量控制与转移支付守恒、端到端的质量守恒与有界性。

## 5. 已知问题

### 5.1 结算的极少数硬失败

`--scenario modern --specialty 2`（产能 24）400 轮 7200 次结算里有 **3 次**解不出来
（残差 1.0、迭代顶到 240 上限），集中在第 358 轮同结构的那三个部门。

**已经修掉的那一档**：存量为正但极小（浮点残渣）时，商品行系数 `(投入−产出)/存量`
会放大到 `1e5` 量级，把 KKT 系统打成病态 —— 这时 400 轮里有 183 次硬失败、1638 次退化。
现在存量低于 `EMPTY_SHELF = 1e-3` 就当作空货架，那一行整条拿掉：
**183 → 3（2.54% → 0.04%）**，退化 1638 → 996。

读数分两级，不许静默继续：

| 读数 | 含义 |
|---|---|
| `settlement_failures` | 没解出来（`converged = false`） |
| `settlement_degraded` | 收敛了，但路上出现过 Cholesky 或回溯失败 |

宏观状态在失败轮仍然有界（库存、指数、成交量都正常），所以影响是局部的；
但 0.04% 不是 0，值得继续查。

### 5.2 模型是确定性的

旧的"申报量乘性涨落"（`fluctuation`）随着申报机制一起删掉了：现在挂出去的是**库存**这个事实，
没有地方可以挂随机因子。于是同一场景下所有种子给出**逐位相同**的结果。
如果要做蒙特卡洛式的稳健性检验，需要重新引入一个随机源（例如挂价本身，
或势的尺度）——目前**没有**。

### 5.3 价格律只剩一个驱动量

旧价格律还有第二项"未满足的意愿"（申报了却没成交的那一份）。申报机制删掉之后
这个观测量不存在了，价格现在**只**由 `库存 / 目标` 驱动。
如果要在这一层加回第二驱动量，需要一个在新架构下有定义的量。

## 6. 复现命令一览

```bash
# 构建
cargo build -p planet_x --bin local_price

# 测试
cargo test -p planet_x --lib

# 主场景：逐商品状态 + 指数 + 货币
cargo run -q -p planet_x --bin local_price -- --scenario modern --capacity 12 --specialty 2 -n 800 --every 100

# 逐轮逐商品表（指数/挂价/成交/库存/投入产出）
cargo run -q -p planet_x --bin local_price -- --scenario modern --capacity 12 --specialty 2 -n 200 --every 10 --trace

# JSONL（每个采样轮次一行，全精度）
cargo run -q -p planet_x --bin local_price -- --scenario modern --capacity 12 --specialty 2 -n 800 --every 400 --json

# 产能扫描
cargo run -q -p planet_x --bin local_price -- --scenario sweep --specialty 2 --polities 3 -n 200

# 技术阶梯：同一部门两个工艺，扫粮食禀赋
cargo run -q -p planet_x --bin local_price -- --scenario ladder --polities 3 -n 200

# 封锁：在 [40, 80) 轮掐掉政权 0 的对外配对
cargo run -q -p planet_x --bin local_price -- --scenario blockade --block-from 40 --block-to 80 --block-polity 0 -n 120 --every 10

# 定向制裁：政权 1 第 0 单元的消费部门
cargo run -q -p planet_x --bin local_price -- --scenario sanction --sanction-polity 1 --sanction-unit 0 --sanction-from 40 --sanction-to 80 -n 120 --every 10
```
